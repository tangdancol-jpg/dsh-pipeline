# 01 · 目标与边界

> 本文件只回答两件事：**要解决什么**（引用真实痛点，不引口号）、**明确不做什么**。
> 设计要点（怎么接钩子、什么时候更新活文档）在 `04-接线点.md`；设施证据在 `02-DSH-原生设施.md`。

---

## 1. 要解决的痛点（全部有现场证据）

### 痛点 A · 上下文被"整份读"撑爆

`lib/context.js` 文件头把这件事写死了：DSH **没有**面向插件的 token 用量接口，
所以插件只能让席位**自报**水位，并配三级阈值（`warnPercent` / `triggerContextPercent` /
`hardLimitPercent`）——最后手段是**换班**。

这说明"读太多"是已经发生的故障，不是假想：
- 席位要看"之前发生了什么"，今天的唯一手段是**读整份文件**（`requirement.md`、
  `handoffs/*.json`、`reports/**`）；
- 读进来就下不去 —— 没有"只取相关切片"的能力；
- 触发换班的代价是**一个席位的全部上下文丢掉**，交接还要再写一份材料。

**要的**：一个能**按相关性取回切片**的 `recall`，取代"整份读"。

### 痛点 B · 跨任务的知识不沉淀

现场：`.pipeline/` 下已经躺着 13 个任务目录（`T-20261011-*` … `T-20261016-*`），
每个目录里都有 `requirement.md`、`handoffs/`、`artifacts/vN/`、`records/`、`audit.jsonl`。

但那是**一单一仓**：
- 新任务从零开始，上一次踩过的坑不会自动出现；
- `pipeline_task_purge` 把终态单清掉 ⇒ 经验随之消失（这是**有意的**清理，不是缺陷）；
- 唯一跨任务带过去的东西是**人**（主对话重新口述背景）。

**要的**：**每项目一个记忆库**，任务终态时把该任务综合成结论落进库里。

### 痛点 C · 用户反复强调的原则每次都靠重说

用户在多个任务里反复给出同一条口径（本单自己就有三条：「优先 DSH 原有功能」
「自己写别全抄」「拆文件」）。这些口径今天住在**某一个任务的 `requirement.md`** 里，
或者只住在**人的记忆**里；换一个项目、换一张单，就要再说一遍。

`pipeline_human_relay` / `pipeline_clarify_reply` 的裁定也同样一次性 —— 裁定完了
就沉在该任务的 `handoffs/` 里，下一个任务不会自动继承。

**要的**：一个**跨项目**的「用户裁定」库（作用域见 §3），让原则住在这里。

### 痛点 D · 已经有的材料没人用

`~/.dsh/storages/session_projcache/sessions/<sid>.json` 里，宿主**已经**替我们把
逐轮摘要物化好了 —— 实测一条会话的 `turnOutline.turns` 有 **373 条**
`{turn, seq, prompt, response}`；同一份里还有 `contextPressure`
（实测 `{surfaceTokens: 205328, contextWindow: 1000000, ...}`）。

今天没有任何机制消费它。**要的**：`reflect` 直接以这份物化结果为输入，
不要自己重跑一遍综合。

## 2. 借鉴 Hindsight 的什么（只借设计，不搬基础设施）

借鉴的**形状**（四条构件 + 两条约束），这是我们认可的设计骨架：

| 借鉴项 | 我们采纳的形态 |
|---|---|
| **三段式** `retain` / `recall` / `reflect` | 采纳。三段各自是独立文件，互不 import 实现 |
| **Mental models（活文档）** | 采纳，但**必须先说清谁触发更新**（见 `04-接线点.md` §3） |
| **Memory banks（隔离库）** | 采纳：每项目一库；另加一个跨项目的「用户裁定」库 |
| **多策略取回** | **只采纳三路**（时间 / 关键词 / 实体），砍掉语义与重排模型（见 §4） |
| **写入异步** | 采纳。写入**绝不阻塞、绝不抛**，失败不影响触发它的那次调用 |
| **取回有显式 token 上限** | 采纳，默认 `4096`；上限的**度量**用 DSH 原生 `ctx.tokenMeter` |
| **实体归一** | 采纳。靠插件已有的**天然主键**做归一，不建实体抽取模型 |

## 3. 作用域（两个库，不新建基础设施）

| 库 | 根 | 住什么 | 复用点 |
|---|---|---|---|
| **项目库** | `<project_dir>/.pipeline/_memory/` | 本项目的任务史、坑、结论 | `.pipeline` 已存在（`lib/project/layout.js:50-58` 的 `pipelineDir`），只是**新增一个下划线子目录**，与 `T-*` 任务目录不冲突 |
| **用户裁定库** | 不落新目录 —— 由插件**运行时注册成一个 skill** | 用户反复强调的原则、跨任务的口径 | `ctx.skills.register()`（`dsh-skill/lib/index.js:193-215`），无需写 `~/.dsh/skills/` |

★ 两条都是**复用**，不是新建：
- 项目库复用 `.pipeline/`（已经过守门白名单，见 `lib/guard/shell.js:171` 的
  `NON_CODE_DIR_SEGMENTS` 与 `lib/guard/decide.js:521` 的"读 `.pipeline/` 放行"）；
- 用户裁定库复用 **skill 机制** —— 它是 DSH 原生的"随记忆增长的活文档"：
  宿主自己在 `agent/pre-step` 把 skill 目录注入成 `<available_skills>`，
  **不必我们再做一次注入**（`dsh-tool-skill/lib/index.js:203-236`）。

**为什么用户裁定库不落 `.pipeline/`**：它是**跨项目**的，而 `.pipeline/` 是**项目内**的。
放进去就变成"跟着项目走"，与"用户原则"的语义相反。

## 4. 明确不做什么

### 4.1 六项"不抄"（用户点名）

1. **不抄 PostgreSQL + pgvector** —— 不引入任何数据库服务。索引是**纯文件 + 内存构建**。
2. **不抄 embedding 模型** —— 不调用任何向量化模型；`recall` 的语义路**整条砍掉**。
3. **不抄交叉编码器重排** —— 不做 learned rerank；重排是**确定性打分**（见 §4.2）。
4. **不抄 Docker 一体化** —— 不要求任何容器；插件仍是一个进程内的 cordis 插件。
5. **不把插件做成 MCP server** —— 能力走**既有工具面**（`lib/tools/kit.js` 的 `tool()`）
   与**既有拦截缝**，不新开一个 MCP 端点。
6. **不自建向量/检索基础设施** —— 不建倒排服务、不建索引服务；索引是**从记忆文件现算**。

### 4.2 被砍掉的取回路（连同理由）

| 路 | 结论 | 理由 |
|---|---|---|
| 语义 / 向量 | **不上** | 没有 embedding 设施；本项目量级（一项目几十到几百条记忆）关键词足够 |
| 交叉编码器重排 | **不上** | 需要模型调用；确定性打分已能给出稳定顺序 |
| LLM 摘要式 reflect | **默认不上** | reflect 优先用**宿主已物化的** `turnOutline`（痛点 D）；真需要模型时也走**既有席位**，不新开 API 调用口 |
| 实体抽取模型 | **不上** | 插件已有天然主键（`task_id` / `change_scope[].path` / `role` / `seat` / `state` / `handoff_id`），归一靠**别名表**就够 |

### 4.3 边界（这一轮与长期）

- **本轮不写任何实现代码**。产出只有 `design/memory/**` 这几份文档。
- **不改既有文件**。新模块只能**新增**；接线点写在 `04-接线点.md` 里由后续批次执行。
- **不动既有机制**：不改状态机、不改守门判据、不改 `.pipeline/` 既有布局。
- 遵守 `plugin/active/CONVENTIONS.md`：一文件一职责、单文件 ≤400 行、
  文件名是"说得出职责的名词短语"。
- **总开关必须管到**：记忆域新增的任何"会写盘 / 会注入"的面，
  都要在 `lib/switch/gate.js` 的 `SWITCH_SURFACES` 里登记（见 `04-接线点.md` §4）。
