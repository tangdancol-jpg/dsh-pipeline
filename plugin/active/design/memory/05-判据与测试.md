# 05 · 判据与测试

> 纪律来自 `CONVENTIONS.md`：**一测试一文件**（§3.2）、测试**可直接 `node` 跑**（§2）、
> **先红后绿**（§7：「每条新测试都要有『旧代码红 → 新代码绿』的运行记录」）、
> 新测试**登记进 `tests/run-all.mjs`**（§6）。
>
> 命名：`tests/m<N>-<slug>-check.mjs`。编号从 `m1` 起，与既有 `p1`–`p8` 不撞号。

---

## 1. 每条判据都必须是**可执行的**

判据的形态：**能被一条命令或一个断言判定的句子**。做不到的不要写进来
（写"记忆要准"这种话等于没写）。

| ID | 判据（可执行） | 怎么判 | 对应测试 |
|---|---|---|---|
| **R1** | 一次 `pipeline_*` 工具调用之后，项目记忆库**多出恰好 1 条**记录 | 调前数行数、调后数行数 | `m4` |
| **R2** | **非** `pipeline_*` 工具（如 `bash`、`read`）调用后，记忆库**行数不变** | 同上 | `m4` |
| **R3** | 记忆追加**失败**（目录只读/磁盘满）时，被包裹的那次工具调用**仍然返回原结果** | 注入一个抛异常的 `fs` 桩，断言调用方拿到原值 | `m3` |
| **R4** | 同一 `task_id` 的不同写法（`T-1` / `T-<日期>-<序号>` / `t-20261011-214043`）归到**同一个实体键** | 断言 `alias()` 三次输出全等 | `m2` |
| **R5** | **不同**实体不被误折（`T-1` 与 `T-2` 的键必须不等） | 断言不等 | `m2` |
| **R6** | 给定同一查询，`recall` 的结果**确定**：跑两次，**字节级相同** | 两次 JSON 序列化比对 | `m5` |
| **R7** | 三路各自单独跑时都能命中；合并后**无重复 id** | 分别调用 + 并集基数检查 | `m5` |
| **R8** | ★ **取回上限是硬的**：任何输入下，返回内容的计价 token **≤ 上限** | `ctx.tokenMeter.estimateMessage` 逐条累加断言 | `m6` |
| **R9** | 超限时**截断的是尾部**（保留分数最高的），不是随机丢 | 断言返回集合 == 排序后前 k 条 | `m6` |
| **R10** | 活文档渲染是**纯函数**：同输入 ⇒ 同输出（无时间戳等不稳定字段） | 跑两次比对 | `m7` |
| **R11** | 活文档写盘**幂等**：内容不变时**不重写**（mtime 不变） | 写两次、比 mtime | `m7` |
| **R12** | ★ **总开关 off ⇒ 记忆域一条缝都不挂**（`mounted()` 里没有记忆缝） | 复用 `tests/switch-off-no-hooks-check.mjs` 的口径 | `m8` |
| **R13** | ★ **总开关 off ⇒ 记忆库一个字节都不变**（跑一轮工具调用后行数不变） | 数行数 | `m8` |
| **R14** | 注入的消息满足宿主形状（`content` 是 block 数组、`source.kind` 是生产者自有的） | 复用 `lib/hostmsg.js:227-232` 的 `isProducerOwnedKind` | `m4`/新增 |
| **R15** | `SWITCH_SURFACES` 里每一条新面都有对应的 `shouldFire` 调用 | 既有 `switch-off-no-hooks-check.mjs` 按条数核对 | `m8` |
| **R16** | 记忆库落在 `<project_dir>/.pipeline/_memory/`，**不落**在任何其它位置 | 断言路径前缀 | `m1` |

★ R8 是整份设计里**最该先立起来**的一条：没有它，"防上下文被记忆撑爆"就只是愿望。

## 3. 边界条件（必须显式规定，否则"怎么实现都不算错"）

按 `pipeline_orchestrate` 的要求，边界要在需求面写死：

| 情形 | 规定 |
|---|---|
| 记忆库**不存在** | `recall` 返回空切片 + 一句人话（**不报错**、**不建目录**）；`retain` 才负责建 |
| 记忆库**为空** | 同上，且活文档渲染出"（还没有记忆）"占位 |
| 库文件**损坏**（半行 JSONL） | **跳过坏行**并计数，在返回里如实报 `skipped:N`；**不整库丢弃** |
| `project_dir` **取不到** | `recall` 返回空 + `reason`；`retain` **静默不写**（不猜落点） |
| 单条记忆**超大**（> 上限） | **单条就截断**并标注 `truncated:true`，不返回半条导致整批超限 |
| 取回上限 `limit` **= 0** | 返回空切片（合法用法：只要计数） |
| 取回上限**超过绝对天花板** | 夹到天花板（建议 8192），并在返回里如实报 `clamped:true` |
| 查询**空串/未给** | 等价于"最近 N 条"（时间路兜底），不报错 |
| 同一实体**大量命中**（如 500 条） | 按时间倒序取够上限即停，**不把内存里的全量都算一遍分** |
| 水位**已过 trigger 阈值** | 本次上限**自动下调**（见 `04` §7.2），并如实报 `budget_reduced_by:'context-pressure'` |
| 写入**并发**（两个缝同时写） | 追加语义：**后写不丢前写**；不做锁，靠 `O_APPEND` 语义 |
| 总开关**在写的过程中被关掉** | 本次写**继续完成**（已经开始了就不半途而废），下一次不再发生 |

## 4. 先红后绿（`CONVENTIONS.md` §7 的硬要求）

每条测试**必须留下"旧代码红 → 新代码绿"的运行记录**。本设计的做法：

1. 先提交**测试**（`tests/mN-*.mjs`）+ **最小骨架**（`lib/memory/*.js` 全部 `throw new Error('not implemented')`
   或返回空），跑一遍 → **红**；
2. 再填实现 → 跑 → **绿**；
3. 两条运行记录（命令 + 输出摘要）写进该批次的交付说明。

★ 判据 R8/R12/R13 的红必须是**真的红**：故意把 `budget.js` 的截断去掉、把 `shouldFire` 去掉，
各自跑一遍确认测试**抓得住**。抓不住的测试等于没有。

---

## 5. 不做的事（测试面）

- **不建测试框架**（`CONVENTIONS.md` §2：`tests/` 「**不**负责测试框架、共享夹具库」）——
  每个文件自带断言与退出码，直接 `node tests/mN-….mjs` 跑。
- **不写"综合大测试"**（§4 明令禁止）。
- **不测实现细节**（不测内部函数名、不测日志文案的全文）——
  只测上表里那些**可执行的判据**。
