# 文件规模闸（不写大文件 · 机器执行）

> 本文档回答一个问题：**"不写大文件"这条规矩，怎么从文档变成插件里会红的闸？**
>
> 背景：`CONVENTIONS.md §4` 早就写了"新增文件 ≤400 行、超了要自证"，但它只是**文档**。
> 结果真实发生过两次：客户端 `client.js` 被硬塞到正好 400 行（"删到最后刚好不超"），
> 面板测试文件涨到 962 行才被拆。文档不会红，模型就会把同一件事堆回大文件里。
>
> 本闸 = 扫描 + 登记表 + 只降不升。设计名：**文件规模闸**（`file-size-gate`）。

- 状态：**已实现**（本设计档与实现同一次提交）
- 代码：`tests/file-size-check.mjs`（闸本身，≤400 行）
- 数据：`tests/file-size-exceptions.json`（登记表，机器可读，**唯一输入**）
- 执行点：`tests/run-all.mjs`（经 `tests/registry.mjs` 登记，作为一套独立测试）+
  `docs/release-checklist.md` 的推送前检查项
- 目录约定：规则的设计档放 `design/conventions/`（本文件）；闸放 `tests/`（`一测试一文件`）；
  登记表与测试同目录（它是测试的输入，不是插件运行期数据）

---

## 1. 四条判据（本文与实现一一对应）

| # | 判据 | 红的情形 | 修法 |
|---|---|---|---|
| R1 | 扫描到的文件必须 **≤ `limit`**（400 行） | 未登记且超限 | 按职责拆；确有 §4 ①②③④ 必要性 ⇒ 登记 + 写 why |
| R2 | **未登记**文件不得落在 `paddingBand`（390–400） | 390–400 的"顶格凑数" | 拆到职责边界；不要删注释凑数 |
| R3 | 登记文件**只降不升**（当前行数 ≤ 登记的 `maxLines`） | 大文件又涨了 | 把新逻辑拆成新文件；或把 `maxLines` 下调（不许上调） |
| R4 | 登记项**不得过期**（文件必须存在） | 文件删了/改名了，登记还在 | 删掉那条登记 |

**为什么 R3 是"只降不升"**：既有大文件是历史债（拆分前遗留），闸不要求一天还清；
但要求**债务不再变大**——往 1532 行的 `index.js` 里再塞 50 行，闸当场红。

---

## 2. 扫描范围（`tests/file-size-exceptions.json → scan`）

```
index.js
lib/**/*.js
presets/**/*.js
tools/**/*.{js,mjs}
tests/**/*.mjs
```

- 跳过的目录：`node_modules`、`.git`、`.pipeline`、`generated`、`design`、`docs`、`locale`、
  `skills`、`examples`、`types`（运行期数据 / 第三方 / 生成物 / 文档，不是源码规模问题）。
- 只认 `.js / .mjs / .cjs`。**数据文件**（如本闸自己的注册表 `.json`）不参与行数判据——
  它是声明表，不是"该拆的逻辑"（与 §4 ① 同口径）。

---

## 3. 登记表（`tests/file-size-exceptions.json`）

```json
{
  "version": 1,
  "limit": 400,
  "paddingBand": [390, 400],
  "scan": ["index.js", "lib", "presets", "tools", "tests"],
  "rules": ["……机器可读的规则摘要……"],
  "note": "……",
  "exceptions": [
    { "path": "index.js", "maxLines": 1532, "kind": "entry", "why": "宿主单入口（§4 ③）…只降不升" },
    { "path": "lib/roles.js", "maxLines": 547, "kind": "table", "why": "§4 ① 单一声明表…" },
    { "path": "lib/guard/rules.js", "maxLines": 400, "allowPadding": true, "kind": "legacy-padding", "why": "既有文件…下次触碰先拆" }
  ]
}
```

- **`why` 必填且不许空**（闸会判红）：它就是 §4 要求的"自证属于哪一条"，
  也是以后判断"这条登记还成不成立"的唯一依据；
- `kind` 只作审计分类：`entry`（宿主单入口，§4 ③）/ `table`（§4 ① 声明表）/
  `legacy`（拆分前遗留，只降不升）/ `legacy-padding`（历史遗留且在 390–400 带内，须 `allowPadding`）；
- **新增登记**只有两种合法姿势：① 新文件确有 §4 必要性（写 why，`maxLines`=当前行数）；
  ② 拆分导致既有登记的行数下降（**下调 `maxLines`**，顺手把债记小）。
- 登记表是**唯一输入**：改规则 = 改这里 + 改闸，不另写第二份规则文本（避免漂移）。

---

## 4. 执行点（怎么让规则"活"起来）

1. **自测里**：`tests/registry.mjs` 登记 `./file-size-check.mjs`，`run-all` 每次都会跑；
   任何超限/顶格/增长/过期登记 ⇒ 这一套红 ⇒ 全量汇总不是全绿。
2. **推送前**：`docs/release-checklist.md` 把它列为必跑项（与 MANIFEST、安装同步并列）。
3. **本地单跑**：`node tests/file-size-check.mjs`（输出红项 + 修法；exit code 非 0）。

> 为什么不做成"守门拦截写文件"：守门看到的是**工具调用参数**，不是文件内容的最终行数
> （分片写、追加写、脚本生成都绕得开）。静态闸在**仓库层**判，才不会被写法绕过。

---

## 5. 与 CONVENTIONS 的关系

| CONVENTIONS | 本闸怎么落实 |
|---|---|
| §4「新增文件 ≤400；超了先自证」 | R1（未登记超限 ⇒ 红）+ 登记表 `why` 强制写自证 |
| §4「不许为凑行数把同一件事切碎 / 也不许塞满」 | R2（未登记不得落在 390–400）+ 设计档说清"按功能结构拆" |
| §5「既有大文件不许再堆；>500 行先抽取再改」 | R3（只降不升）+ R4（登记过期即红） |
| §4「一个文件只有一个改动原因」 | 不作机器判据（无法自动判断职责），由登记 `why` + 评审兜住 |

**诚实说明**：本闸能防"又写大了"，防不住"拆得不对"（切碎同一职责、边界错）。
后者靠 §4 的 `why` 自证 + 评审，不假装机器能判。

---

## 6. 存量债务（一次性登记，之后只降不升）

实现时一次性登记了 **88 个既有文件**（拆分前遗留的超限文件 + 3 个历史滞留在 390–400 带的文件），
每个都带 `why` 与当前 `maxLines`。这不是"豁免"：

- 它们**不能再长**（R3）；
- 触碰这些文件时，按 §5「先抽取再改」，把要动的那块搬进新文件；
- 拆小了就**下调** `maxLines`（债务记小），全量自测会持续盯着。

## 7. 测试（`tests/file-size-check.mjs`，14 条）

| 组 | 断言 |
|---|---|
| A 登记表 | JSON 可解析 / 字段齐全 / 每条有 path+maxLines+why |
| B 磁盘事实 | 扫描到 375 个文件 / 未登记超限=0 / 未登记顶格=0 / 已登记未增长 / 无过期登记 / 顶格带只允许登记旧文件 |
| C 判据自证 | 合成输入证明：未登记超限必红、未登记顶格必红、登记后增长必红、过期登记必红、合法登记与未超限文件不误伤 |

> C 组存在的理由：只测"当前仓库是绿的"无法证明闸有牙（把所有文件挪走也能全绿）。
> 合成输入证明四条判据各自会红。

---

## 8. 已知限制 / 不做的事

- 不判"职责边界对不对"（无法自动化），只判行数与增长；
- 不管运行期生成物（`node_modules`、`.pipeline`、项目交付物）——若以后要把规则延伸到
  **任务交付物**（席位的项目代码），应走 `pipeline_change_audit` 那一层单独设计，混进来会让闸的判据不纯；
- 不做自动拆分 / 自动登记（机器改代码风险高于收益）；
- 数据文件（JSON 登记表、schema 表）不受行数判据约束。
