# 文件规模提醒（150 / 300 / 400 三档，程序自动发起）

> 本文档回答一个问题：**"不写大文件"的提醒，怎么由程序自动发起，而不是靠人记得问？**
>
> 用户需求（2026-10-18 逐字）：
> 「文件行数大于 150 就开始提醒 ai，自动发起对话询问：**有必要写这么大吗？是因为顺手写一起了
> 还是功能需求**；大于 300，二次询问；400 时三次提问：**一定这个写法吗？有没有更优的写法？
> 你能不能上网调用 Search 接口和 Fetch 接口查询有没有更优质的写法。**」

- 状态：**已实现**
- 代码：`lib/size-reminder.js`（阈值/文案/去重状态）+ `lib/guard/hook-size.js`（两条拦截缝）
- 测试：`tests/size-reminder-check.mjs`（20 项，登记在 `tests/registry.mjs`）
- 与 `01-文件规模体检.md` 的关系：**体检**是"报告给你看"；**提醒**是"把问题直接发给正在写文件的 AI"。
  两者都不判红、不阻塞（拆分判断仍在人和评审手里，见 `CONVENTIONS §4` 四问）。

---

## 1. 三档阈值与问句（用户原话即判据）

| 档 | 触发（行数） | 问什么 | 额外要求 |
|---|---|---|---|
| 1/3 | **> 150** | 有必要写这么大吗？是因为顺手写一起了还是功能需求？ | 只是顺手 ⇒ 按职责拆；确实是功能需求 ⇒ 继续 |
| 2/3 | **> 300** | 同一句**再问一次** | 如果仍答"功能需求" ⇒ 用一句话说明"为什么必须放在同一个文件里" |
| 3/3 | **≥ 400** | 一定要用现在这个写法吗？有没有更优的写法？ | **实际调用** `web_search`（Search 接口）与 `web_fetch`（Fetch 接口）查更优写法，回复里说明查了什么、结论是什么 |

- 150/300/400 可由配置项 `sizeReminder.firstLines/secondLines/thirdLines` 覆盖；
- 第 3 档文案明确要求"实际调用"，不是嘴上说"我去查查"（与 `pipeline_full_test` 的"直达条件"同口径：能验的就验）。

---

## 2. 怎么做到"程序自动发起"

两条**既有**拦截缝，不新挂事件：

```
write / edit / apply_patch …（写类工具）
  └─ tools/post-execute  →  lib/guard/hook-size.js · createSizeWatchHook
        · 只对管线席位（seatOf(agentId) ≠ null）
        · 取刚写的文件路径 → 数行数 → levelFor(150/300/400)
        · 同文件同档只记一次（去重状态在 lib/size-reminder.js）
        · **不改工具结果**（原样 next()）
  └─ agent/pre-step  →  lib/guard/hook-size.js · createSizeAskHook
        · 到了下一次开步，把待问条目用 hostMessage() 包成**用户消息**
        · spread 下游 decision 后追加 messages（形状是宿主硬契约）
        · 每次开步最多 2 条（maxAsksPerStep），从高档开始
```

AI 看到的就是一条**用户消息**：「【文件规模提醒 1/3】你刚写完 `x.js`……问自己一句……」
—— 它会像回答用户一样回答这个问题（继续说明理由，或按职责拆）。

- 注入点已登记进 `lib/hostmsg.js` 的 `HOST_INJECTION_SITES`（`pre-step-file-size-ask`，
  `form: 'file-size-reminder'`），自测按登记表核对形状；
- 两条缝都登记在 `lib/switch/gate.js` 的 `SWITCH_SURFACES`（关掉功能 ⇒ 两条都不挂 = 不留一句话）。

## 3. 纪律（缺一条就会变噪音或事故）

| # | 纪律 | 判据 |
|---|---|---|
| ① | **只提醒，不否决** | 不改工具结果、不 block、不抛；`post-execute` 钩子第一句是 `next()` 直通 |
| ② | **只对管线席位** | `seatOf(agentId)` 为 null ⇒ 直通（用户自己的会话、别的项目的会话一律不管） |
| ③ | **只看写类工具 + 代码文件** | `write/edit/apply_patch…`；扩展名白名单；`node_modules/.pipeline/dist/generated…` 跳过 |
| ④ | **去重 + 有界** | 同文件同档只问一次；每步最多 2 条；状态表上限 512 个 agent |
| ⑤ | **关掉功能 = 不吭声** | 两条缝随总开关真挂真摘（`switch-off-no-hooks-check` 断言"开=8 → 关=0 → 再开=8"） |

## 4. 配置

`lib/config.js` 的 `DEFAULTS.sizeReminder`：

```js
sizeReminder: {
  enabled: true,       // 关掉 ⇒ 整条提醒链不做事
  firstLines: 150,     // >150 ⇒ 1/3
  secondLines: 300,    // >300 ⇒ 2/3
  thirdLines: 400,     // ≥400 ⇒ 3/3（并要 web_search / web_fetch）
  maxAsksPerStep: 2,   // 每次开步最多投几条
}
```

阈值与文案**唯一出处**在 `lib/size-reminder.js`（`levelFor` / `messageFor`），测试直接 import 它，
不在测试里抄第二份文案。

## 5. 测试（20 项，先有红灯再写实现）

| 组 | 断言 |
|---|---|
| A 阈值 | 150→0 / 151→1 / 300→1 / 301→2 / 399→2 / 400→3；自定义阈值生效；非法行数不提醒 |
| B 文案 | 第 1 档含「有必要写这么大吗」「顺手」「功能需求」；第 2 档"再问一次"；第 3 档含「一定」「更优」并点名 `web_search`/`web_fetch`；不出现绝对路径 |
| C 过滤 | 只有写类工具；只有代码文件；相对路径按 cwd 解析 |
| D 状态 | 同档只问一次；长大后升级再问；每步最多 2 条且高档优先；低于阈值不排队；`enabled:false` 不做事 |
| E 接线 | `post-execute` 不改结果；`pre-step` 注入的用户消息形状合法（id/role/content/`source.form`）；注入后清空；读工具不触发；非席位直通 |

## 6. 已知限制（如实列出）

- **只覆盖写类工具**：`apply_patch` 等多文件补丁只认第一个路径；`bash` 里用脚本生成的大文件观察不到
  （那是 `tools/post-execute` 拿不到内容的边界，不假装能覆盖）；
- 行数按**磁盘上的最终文件**数，不按模型这次写的内容数（append 场景也准）；
- 提醒**不保证 AI 一定拆**：它只把问题摆到 AI 面前（程序自动发起对话），最终判断仍是 AI + 评审；
- 第 3 档要求"调用 Search/Fetch"依赖该席位预设里确实挂了 `web_search` / `web_fetch` —— 没挂时
  AI 会如实说"没有这个工具"，这不算提醒失败。
