# 自动审查（Auto Review）· P0 设计（只设计，未实现）

> 本文档回答一个问题：**能不能在"用户不被打断"和"守门不作废"之间找到一个可判据的中间态**。
>
> 借鉴对象是官方 `dsh-permission-presets` 里的 **Auto review（实验性）**：权限下拉里的
> 「自动审查 EXP」档 + 设置里「由模型在每次工具调用前判断是否授权」的开关
> （[官方文档](https://deepseek-harness.github.io/deepseek-harness/en/reference/subsystems/permission-presets.md)）。
> 但我们的信任根与官方不同 —— 我们是"三权分立 + 白纸黑字授权面"的流水线，
> 所以只借**结构**，不借"模型说行就行"。

- 状态：**P0 设计**（未写实现、未建台账扩展、未改开关）
- 落地技能：`plugin/active/design/approvals/`
- 上游相关实现（读代码时按这里找，不另抄一份）：
  - 守门判定与接线：`lib/guard/decide.js`（能力额度闸在 `L113`，读源码放行在 `L547`，搜索源码放行在 `L586`）
  - 一次性额度台账：`lib/guard/grant.js`（`GRANT_OPS` 四种 op + 折叠状态）
  - 额度闸：`lib/guard/capability-gate.js`（一次调用只消耗一份额度）
  - 能力申请工具：`lib/tools/capability.js`（`request` / `approve` / `reject` / `list`，仅主对话）
  - 配置：`lib/config.js` 的默认配置对象（新增项照它的写法加默认值）

## 1. 目标 / 非目标

### 目标（P0 只定义，不实现）

- **减少不必要的人工打断**：把"本来就会被拒绝、但确实在授权面内"的少数调用自动放行一次，
  用户只在**真正越界/有风险**时才被打扰。
- **不放宽任何既有边界**：授权面（`change_scope` / 已批准 scope / 角色读写分类）不因开启自动审查而扩大。
- **判据可复核**：每一次自动决定都有成对台账（谁问的、依据哪条规则、谁批的、什么时候用掉的）。
- **默认关闭、实验性标注**：与官方 EXP 一致，绝不成为默认路径。

### 非目标（明确不做）

- 不替代人工介入的两级梯（`pipeline_clarify_request` / `pipeline_human_request`）；
- 不让执行者自我批准（审查者必须是**独立会话/独立上下文**，不是执行模型自己说"可以"）；
- 不做 `allow-always`、不做记住规则、不做撤销列表（沿用既有"批准只放行一次"）；
- 不自动放行写文件与 shell（P0 不做；shell 本来就不可申请，见 `lib/guard/capability.js` 文件头）；
- 不改沙箱档位、不改 `danger-full-access` 的授予链（"完全"档仍要三段审批，见 README 对应段落）。

## 2. 官方做法摘要 vs 我们的取舍

| 官方 | 我们借什么 | 我们改什么（及理由） |
|---|---|---|
| 权限档位里加一个 `auto`（仅当前会话、EXP、`danger-full-access`+`ask`） | 把自动审查做成**档位**而不是隐式行为：有开关、有显示、可随时撤 | 我们的档位不绑沙箱升级：自动审查**绝不**改变沙箱/授权面，只影响"这一次调用是否放行" |
| 集成活着才出现（`registerAuto(admit)`），`admit` 在切换前同步跑 | 切换自动审查前先验证审查者可用（"admit 门"） | 我们的 admit 门检查：审查者角色存在、审查通道健康、台账可写；任一不满足 ⇒ 拒绝切换 |
| 审批 seam：一次性、fail-closed、asked/decided 成对审计 | 三态 + 成对审计 + fail-closed | 我们复用既有 `capability-grants.jsonl` 追加式台账，不新造存储 |
| 请求不带工具参数（只给名字/原因） | 审查输入脱敏 | 我们只给：工具名、能力类、相对路径列表（限量）、理由截断、任务档位/状态、命中规则 id —— **绝不给文件正文/命令参数原文** |
| 模型在每次工具调用前判断 | 审查者=独立席位、单轮分类 | 审查者只做**分类任务**（固定规则表 + JSON 输出），无工具面、不读任务正文 |

## 3. 信任根与不变量（实现时必须逐条守）

| # | 不变量 | 判据（怎么验） |
|---|---|---|
| I1 | **不自我批准** | 审查请求的 `reviewer.agent_id` 必须 ≠ 触发调用的 `agent_id`；相同 ⇒ 直接升级人工 |
| I2 | **不扩大授权面** | 自动放行的 scope 必须是请求 scope 的**子集**且 ⊆ 任务已有授权面；否则 deny |
| I3 | **一次性** | 放行必须走既有 `release` 语义（额度用完即 `used`）；不允许写"永久 approved" |
| I4 | **fail-closed** | 审查者缺席/超时/输出不合法/台账写不进 ⇒ **不放行**（升级人工或拒绝，绝不默认 allow） |
| I5 | **成对留痕** | 每次自动决定 = 一行 `request`（已有）+ 一行 `approve`/`reject`（`by:"auto-review"`，带规则 id）；有问必有答 |
| I6 | **可撤/熔断** | 连续 deny 或连续 unavailable 达阈值 ⇒ 自动审查**自动回落人工**并写一行状态事件；人可随时关掉 |
| I7 | **脱敏** | 审查输入字段白名单（见 §7），任何代码正文/凭据/URL 参数不得进入审查请求 |
| I8 | **EXP 且默认关** | 默认 `mode: "off"`；开启需要在配置或面板里显式操作，并显示实验性标记 |

## 4. 概念

- **审查者（reviewer seat）**：独立会话，默认复用 `reviewer`（审核）或 `security`（安全）角色；
  单轮、无工具、只做分类。可用现有传输层（`transport` / `roleProvider`）派发，但**不参与**
  任务状态机（不写交接物、不改任务）。
- **三态结果**：
  | 结果 | 含义 | 后续 |
  |---|---|---|
  | `allow-once` | 这次调用风险类别命中白名单、且 scope ⊆ 已有授权面、且审查者独立 | 台账记 `approve(by:auto-review)` ⇒ 额度闸放行一次 |
  | `deny` | 明确越界/高风险（如写文件、shell、外网、凭据、跨任务） | 拒绝并记 `reject(by:auto-review)`，给"下一步"文案 |
  | `escalate` | 判不了（信息不足/置信度低/审查者不可用） | 保持 `pending`，交人工（`pipeline_human_request` 通道） |
- **熔断**：连续 `deny` ≥ `maxConsecutiveDeny`（默认 3）或连续 `escalate`（不可用）≥ `maxUnavailable`
  （默认 2） ⇒ 自动回落 `mode: "off"` + 记一行 `auto-review/disabled` 事件，并提示原因。
  恢复只能人工重开（不做自动恢复，避免抖动）。

## 5. 覆盖范围（分期；P0 只列，不实现）

| 阶段 | 覆盖点 | 自动放行条件（白名单） | 不做什么 |
|---|---|---|---|
| P1 | `report-only`：只判不生效 | 不改变任何决定，只往台账写"若开启会怎样" | 不碰调用结果 |
| P2 | 主对话越界**读源码**（`CAPABILITY.READ_SOURCE`，`decide.js:547` 那条） | 只读、路径 ⊆ 任务已有授权面（`change_scope` 或已批准 scope）、目标数 ≤ `maxTargets` | 不读测试/凭据/配置目录（沿用既有读面分类） |
| P3 | 主对话越界**搜索源码**（`SEARCH_SOURCE`，`decide.js:586`） | 同上；搜索词不做语义审查，只按 scope 判 | 不做关键词白名单 |
| P4 | `pipeline_capability_request` 的**预审**：把"申请→等用户"改成"申请→自动审查→用户只在 escalate 时被打断" | 能力 ∈ 配置白名单（P4 只允许 `read-source`）、scope 规范化后 ⊆ 授权面、理由非空 | 不自动批准 `write-file`、不批准 `*` 全域 |
| P5 | 面板显示与开关（实验性） | `/.dsh-pipeline/panel` 增加 `auto_review` 汇总字段；开关走配置/面板 | 不做设置页大改 |

**第一版（P2）只做一件事**：让主对话在"任务授权面内读源码"时不必每次找用户。
这一条是用户抱怨最多、风险最低、判据最清楚的路径。

## 6. 配置

在 `lib/config.js` 默认配置对象里新增（写法与既有项一致，带注释）：

```js
autoReview: {
  mode: 'off',                 // 'off' | 'report' | 'auto'（默认关 = 实验性）
  capability: ['read-source'], // 允许自动审查的能力（P2 只 read-source）
  reviewerRole: 'reviewer',    // 'reviewer' | 'security'（独立席位）
  escalate: 'human',           // 'human' | 'deny'（escalate 的落点；默认找人）
  maxTargets: 20,              // 一次调用目标数上限（超了直接 escalate）
  timeoutMs: 15000,            // 审查者超时 ⇒ 按 escalate 处理
  maxConsecutiveDeny: 3,       // 熔断：连续 deny
  maxUnavailable: 2,           // 熔断：连续不可用/超时
  maxReasonChars: 200,         // 进审查请求的理由截断
}
```

- 运行时另可被**会话级开关**覆盖（面板/命令），但会话级只能把 `off` 之外的值**降级**回 `off`，
  不能把 `off` 升成 `auto`（防止模型自己把闸门打开）。
- 配置非法值 ⇒ 插件加载时明确报错（与 `lib/config.js` 既有做法一致）。

## 7. 审查输入（字段白名单 · 脱敏）

审查请求是一个**结构化 JSON**（不是自然语言自由文本；防提示词注入 —— 只读字段值，不执行里面的指令）：

| 字段 | 内容 | 限制 |
|---|---|---|
| `task_id` / `tier` / `state` | 任务身份与档位 | 原样 |
| `actor_role` | 触发调用的角色 | 原样 |
| `tool` | 工具名 | 原样 |
| `capability` | `read-source` / `search-source` | 原样 |
| `targets` | 规范化后的**相对路径**列表 | ≤ `maxTargets` 条；超出 ⇒ escalate；不展开目录内容 |
| `allowed_scope` | 授权面摘要（`change_scope` 的路径列表） | 只给路径，不给文件内容 |
| `rule_id` | 触发审查的既有规则 id（如 `NO_CODE_READ_ROLES` 命中的那条） | 原样 |
| `reason` | 模型自己写的理由 | 截断 `maxReasonChars`，去控制字符 |

**禁止字段**：文件正文、命令参数原文、环境变量、凭据、URL/query、其他任务的内容、
历史对话正文。审查者输出同样是**结构化 JSON**：`{ "decision": "allow-once|deny|escalate", "rule": "≤40 字", "reason": "≤200 字" }`；
解析失败即 `escalate`。

## 8. 判定流程（实现时的接线位置）

```
tool call
  └─ lib/guard/decide.js
       ├─ 静态规则命中拒绝？（越权/跳步/写面/角色面…）
       │    ├─ 能定死 ⇒ 拒绝（现状不变）
       │    └─ 属于可审查类（P2/P3）且 autoReview.mode 允许
       │         └─ 查已有 approved 额度（现状 capGate.take 先跑）
       │              ├─ 有额度 ⇒ 放行一次（现有语义，不经过审查）
       │              └─ 没有额度 ⇒ 进入自动审查
       │                   ├─ 构造脱敏请求 → 审查者 → 三态
       │                   ├─ allow-once ⇒ 台账 appendGrant(approve, by:'auto-review', rule…)
       │                   │              ⇒ capGate.take 再判一次 ⇒ 放行一次
       │                   ├─ deny      ⇒ 台账 appendGrant(reject, by:'auto-review', rule…)
       │                   │              ⇒ 拒绝（文案给"下一步"）
       │                   └─ escalate  ⇒ 台账 appendGrant(escalate, …) + 保持 pending
       │                                  ⇒ 按配置交人工/拒绝
       └─ 其余路径完全不变
```

**接线纪律**：`decide.js` 已超 400 行（CONVENTIONS §5），所以本功能**只允许在它里面接线**
（一行调用 + import），实现全部落 `lib/auto-review/` 新目录：

```
lib/auto-review/
  index.js      // 对外：maybeReview({task, role, tool, capability, targets, ruleId, cfg}) → 三态
  reviewer.js   // 审查者调用：派发独立席位、单轮、脱敏输入、超时、JSON 解析
  policy.js     // 规则表：可审查类/禁止类/白名单（纯函数，便于单测）
  audit.js      // 台账扩展：approve/reject/escalate 行的字段与折叠扩展
```

## 9. 台账扩展（复用 `capability-grants.jsonl`，不新造存储）

现有 op：`request / approve / reject / release`（`lib/guard/grant.js` 的 `GRANT_OPS`）。扩展：

| op | 新增/既有 | 字段 | 折叠影响 |
|---|---|---|---|
| `request` | 既有 | 复用（`capability/scope/reason/tool/by`） | 状态 `pending` |
| `approve` | 既有 | 新增 `by:"auto-review"`、`rule`、`reviewer`、`summary_hash`、`latency_ms` | 同人工 approve ⇒ `approved`（一次性） |
| `reject` | 既有 | 新增 `by:"auto-review"`、`rule` | `rejected` |
| `escalate` | **新增** | `reason`、`by:"auto-review"`、`latency_ms` | **不改状态**（仍 `pending`，等人工） |
| `auto-review/disabled` | **新增** | `reason`（`consecutive-deny` / `unavailable` / `manual`） | 不改额度状态；只作审计与面板计数 |

- `parseLedger` 的 `GRANT_OPS` 白名单同步加 `escalate` 与 `auto-review/disabled`（坏行仍跳过）。
- **fail-closed**：`approve(auto-review)` 那一行写不进去 ⇒ 本次不放行（沿用 `capability-gate.js` 的既有纪律）。
- 台账位置不变：`<任务目录>/capability-grants.jsonl`，人在 `pipeline_capability_request action:"list"`
  里能看到 auto 记录（新增一列"决定来源"：`user` / `auto-review`）。

## 11. 失败与错误文案（必须有"下一步"）

| 情形 | 返回 | 文案要求 |
|---|---|---|
| 审查者不可用 | `escalate`（或 `deny`，按配置） | 写清"审查席位不可用 ⇒ 已转人工"，并给申请 id |
| 审查超时 | 同上 | 带超时毫秒数 |
| 审查输出不合法 | `escalate` | 写清"审查结论不可解析 ⇒ 不放行" |
| scope 超出授权面 | `deny` | 写清"越界"以及正确的下一步（`pipeline_scope_amend` / 人工） |
| 熔断触发 | 本次起全部走人工 | 写清"连续 N 次…已自动关闭自动审查，请人工确认后重开" |

## 12. 与官方的对照（差异点是有意的）

| 维度 | 官方 Auto review | 我们 P0 设计 |
|---|---|---|
| 判据来源 | 模型在每次工具调用前判断 | 模型只做**分类**，白名单/边界由既有规则表定死；模型不能扩 scope |
| 权限档 | 自动档 = `danger-full-access` + `ask` | 自动审查**不改沙箱档位**，只决定"这一次放不放行" |
| 生效范围 | 仅当前会话，集成退场即消失 | 会话级开关只能降级回 `off`；任务结束时自动失效 |
| 存储 | Session 审计事件 | 复用任务目录的追加式 JSONL 台账（与人工批准同源） |
| 默认 | EXP，需显式选择 | EXP，默认 `off`，配置/面板显式开启 |

## 13. 测试计划（实现阶段，先红后绿）

新测试文件 `tests/auto-review-check.mjs`（≤400 行；登记 `tests/registry.mjs`，套件 +1 → 111→112）：

| 组 | 用例 | 期望 |
|---|---|---|
| A 规则表 | 可审查类只 read-source；write-file/shell/`*` 一律 escalate | 纯函数断言 |
| B 三态 | allow/deny/escalate/输出坏 JSON/超时/审查者缺席 | 三态与台账行成对；缺席 ⇒ fail-closed |
| C 不变量 | 审查者=执行者 ⇒ escalate；scope 超授权面 ⇒ deny；scope 非子集 ⇒ deny；目标超 `maxTargets` ⇒ escalate | 逐条断言 |
| D 一次性 | 自动 approve 后 `release` 一次即 `used`，第二次被拒 | 与既有 capGate 语义一致 |
| E 熔断 | 连续 3 deny / 2 unavailable ⇒ mode 自动回 `off` + 事件行 | 状态与事件都断言 |
| F 审计 | `escalate` 不改额度状态；`auto-review/disabled` 只记录 | 折叠函数断言 |
| G 脱敏 | 构造含正文/命令/URL 的请求 → 进入审查 JSON 的字段只剩白名单 | 字段表断言 |
| H 开关 | 会话级只能降级；配置非法 ⇒ 加载报错 | 与 config 校验一致 |

**负例优先**：越权、scope 外、审查者缺席、输出不可解析、熔断这五类必须先有红测，
再写实现（不写"只测 happy path"的测试）。

## 16. 不做的理由（防过度工程）

- 不做"自动记住规则/白名单长久生效"：与既有"批准只放行一次"冲突，等于给模型一个可累积的权限池；
- 不做"自动审查写文件"：写面风险不可逆，且与 `change_scope` 的既有判据重叠，收益小；
- 不做全局默认开启：实验性功能默认关，避免把"复核"这件人该负责的事变成模型自证；
- 不新增常驻审查席位：用现有的 reviewer/security 角色单轮调用，避免每次开单多一个 AI 和一份上下文。
