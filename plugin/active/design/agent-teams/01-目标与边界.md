# Agent Teams 深度整合 · 01 目标与边界

> 本文件是**决策记录**：官方 Agent Teams 的硬事实 → 由此产生的设计取舍 → 验收判据。
> 实施落点见 [`02-接线点与任务拆分.md`](02-接线点与任务拆分.md)。
> 证据：官方服务源码抽自 `app.asar`（`_recon` 文件不在仓库内，路径写在每条事实后面），
> 行号以 `@deepseek-ai/dsh-experimental-agent-team@0.2.1-rc.2/lib/index.js` 为准。

---

## 1. 目标

把 dsh-pipeline 的**派活**与**唤醒投递**接到官方 Agent Teams 原语上，新增一条
**一等通道 `transport: 'team'`**：

| 能力 | 官方原语 | pipeline 里的落点 |
|---|---|---|
| 派一个角色 | `spawnTeammate`（= `spawn_teammate`） | `TeamTransport.spawnRole` |
| 给席位投消息 / 唤醒 | `sendMessage`（= `send_message`） | `TeamTransport.notifyRole` |
| 名单与状态 | `listMembers`（= `list_agents`） | 反查 `sessionId → teammate name`、容量诊断 |
| 打断 | `interrupt`（= `interrupt_agent`） | `notifyRole({ stop:true })` |
| 共享任务板 | `createTask/getTask/listTasks/updateTask`（= `team_task_*`） | `lib/team/board.js`（pipeline 任务 ↔ Team 任务镜像） |
| 等待变化 | `waitForChange`（= `wait_agent`） | 回执里给主对话的使用指引（不阻塞宿主） |

**非目标**（本批次不做，写清以免顺手扩）：

- 不替换/删除既有 `session` / `subagent` / `manual` 通道；`auto` 的既有优先级不变。
- 不改唤醒链（`lib/wakeup/**`）：唤醒只投主对话，与"谁当席位"无关。
- 不改 `pipeline_dispatch` 的 output schema（仍是 5 个键）。
- 不动 `PLUGIN_INJECT`（精确 `['tools','sessionProjections']`，`agentTeams` 一律 `ctx.get()`）。
- 不给 teammate 改 model / permission preset 的"假能力"：能钉就钉并读回，钉不上就**如实记未生效**。

## 3. 决策（Lead 裁定，写死）

### D1 · 新通道，不替换
`createTransport` 增加 `mode === 'team'`。`auto` **保持既有优先级**（Session 优先）；
Team 只在显式 `transport: 'team'`，或 `transport: 'auto' && teamAuto === true` 时启用。
理由：不改变现有生产行为；`auto` 的语义已在 `transport/index.js` 注释里写死。

### D2 · 角色人格：写进派活单（因为 preset 下发不了）
`TeamTransport.spawnRole` 渲染的正文 = `renderDispatchBrief(...)` + **角色固定提示词**
（`presets/src/<role>/` 的 `prefix.md` + `prompt.md` + `suffix.md`，经 `presets/render.js`
的 `composePrefix/composeSuffix` 读，**不新抄一份**）。
`slotEvidence.mode` 记 `UNAVAILABLE`，`detail` 写明"官方 spawnTeammate 无 agentPreset 参数（F1）"。

### D3 · 四槽：能钉的钉、钉不上的如实记
- `permission` / `model` / `reasoning`：spawn 成功后用既有 `applyPermissionSlot` /
  `applyModelSlot`（用 `member.id` 当 sessionId）补钉并**读回核对**；读不回 ⇒ `ok:false`。
- `mode`：**不钉**，如实记 `UNAVAILABLE`。
- `teamStrictSlots: true` 时：任一槽"显式非默认"却钉不上 ⇒ **拒绝派活**（`ok:false` + 可读报告）。
- 绝不把没生效的槽写成"已生效"（F11 教训）。

### D4 · 机制派活（无活 Agent）
`spawnRole(spec)` 里 `spec.parent` 不是活 Agent ⇒ 返回 `ok:false`，报告写明：
"官方 Team 通道需要活着的 Lead Agent 作 caller（F3）；机制发起的补派请用 `transport:'session'`
或人工复制"。**不静默降级**。

### D5 · teammate 命名
`name = <teamNamePrefix>-<task 小写>-<role>[-<seat 序号>]`（kebab；默认前缀 `p`）。
- `seat` 里的 `#` 归一成 `-`；`tester#tester` 这类旧席位键先归一（同 `wakeup/keys.js` 口径）。
- 重派/继任：同名已存在 ⇒ **复用**该 member 并 `sendMessage` 投递（不重复 spawn）；
  `reassign:true` 要"换人" ⇒ 新名追加 `-r<N>`。
- name ↔ member.id ↔ (task,role,seat) 的映射由 `listMembers` 现查（不新开落盘格式）。

### D6 · 容量到顶
`TEAM_MEMBER_LIMIT` / `TEAM_MEMBER_NAME_TAKEN` 等 `TeamError` 一律翻译成可读失败：
写明当前 profile 的 `maxMembers`、已用成员数、以及两条出路（调大 profile patch / 新开会话）。
`available()` 仍为 true（服务在）；容量问题在 spawn 时如实失败。

### D7 · 投递超长
`sendMessage` 的 64KB 上限：投递前按 UTF-8 字节截断正文，追加
`…（已截断：官方 sendMessage 上限 65536 字节）`，并在 `note` 里如实标注。**不静默丢内容**。

### D8 · 守门：新工具面必须被分类
官方新插件带来的工具（team / 持久终端 / 会话搜索 / 工作树 / Ralph / 子代理 …）必须进守门分类：
1. **shell 旁路**：`terminal_*` 已是 shell 类；但 `terminal_send` 的命令在 `text` 里，
   `collectCommandStrings` 必须按工具名补扫 `text`（否则"测试/审核不得改代码"可绕过）。
2. **越权面**：绑定角色的会话一律拒绝 team 协作类、委派类、插件管理类、会话搜索类工具
   （名单见 02 文件 §3），失败原文要点名"这条在你这个角色上等于绕过三权分立"。
3. **工具面收紧**：`deriveToolFace()` 的 `denied` 列表要包含上述 host 工具，
   让席位**看不见**它们（不只是调用时被拒）。
4. 主对话（main）不因此收窄既有能力；但 team 协作类工具对 main 是**允许**的（它就是 Lead）。

### D9 · wait_agent 的位置
不是宿主轮询器。`pipeline_dispatch`（team 通道）的回执 `summary` 里提示主对话：
"席位是官方 Team member，可用 `wait_agent` 等变化，不必轮询 `pipeline_status`"。
官方工具本身已在主对话工具面里，pipeline 只负责**把语义接上**。

### D10 · 任务板镜像（team_task_*）
`teamBoard: 'auto'`（默认）= team 通道且服务可用时镜像；`'off'` = 关。
- 开单 → `createTask(subject, description, writeScopes)`；
- 派活成功 → `updateTask(claim/reassign)`（revision CAS，冲突重读重试一次）；
- 关单/取消 → `updateTask(complete)`。
- 落点：`.pipeline/<任务>/team-board.json` 记 `{taskId, revision, lastAction}`。
- **失败不阻断流水线**（任务板是辅助面）：错误进 `audit.jsonl`（`team:board-*`）+ 回执 `note` 明说。

## 4. 验收判据

1. `transport: 'team'` 且宿主有 `ctx.agentTeams`：`pipeline_dispatch` 真的创建一个**具名 teammate**
   （官方名单里查得到，名字合法、可地址），令牌与 `member.id` 二次绑定，派活单正文含角色提示词。
2. 同一席位重复派活 ⇒ 复用同一 member（不触发 `TEAM_MEMBER_NAME_TAKEN`）；`reassign` ⇒ 新名 `-r2`。
3. `notify_only` / 孤儿重投 / 失联唤醒走 `sendMessage`，且 `stop:true` 走 `interrupt`。
4. 四槽：`mode` 记 `UNAVAILABLE`（写明 F1）；permission/model 钉上并读回；钉不上 `ok:false`。
5. `spawn:false` ⇒ 一次宿主调用都不发（含 `spawnTeammate`）。
6. 无 `agentTeams` / 无活 caller / 容量到顶 ⇒ `ok:false` + 可读报告，绝不静默降级。
7. 守门：角色会话调 `subagent` / `ralph` / `workflow` / `send_message` / `team_task_*` /
   `plugin_manager` / `session_search` 被拒（原文点名原因）；`terminal_send` 里写文件的命令被拦。
   席位工具面收紧的 `deny` 含这些新工具。
8. 任务板镜像：开单/派活/关单三处可观察到 `createTask` / `updateTask` 调用；失败只记 audit。
9. 既有 3319 条测试**一条不许改期望值**；新增套进 `tests/registry.mjs`，`run-all` 全绿。
