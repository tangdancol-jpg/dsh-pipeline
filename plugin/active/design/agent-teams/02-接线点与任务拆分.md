### 1.1 `TeamTransport` 契约（与既有三方法一致 + 扩展）

```js
class TeamTransport {
  kind = 'team'
  available()                       // ctx.get('agentTeams') 有 spawnTeammate/sendMessage/listMembers
  probe()                           // probeTeamChannel(ctx)
  async spawnRole(spec)             // spec = {task, roster, role, seat, spawn, parent, signal, permission, mode, model, reasoning}
                                    // → {ok, agentId, sessionId, token, via:'team', memberName, brief, slots, slotEvidence, note}
  async notifyRole(spec)            // spec = {task, roster, role, seat, sessionId, sender, agentId, message, stop}
                                    // → {ok, messageId, note}
  async listMembers(caller)         // → TeamMemberView[]（拿不到返回 []）
  async interrupt(caller, name)     // → {ok, previousStatus, note}
}
```

**spawnRole 步骤**（顺序即判据）：
1. `spec.spawn === false` ⇒ `manualSpawnResult(deps, spec, '调用方显式传了 spawn=false：')`，**零宿主调用**。
2. `probe()` 不可用 ⇒ `{ok:false, via:'team', unreachable:true, probe, report}`，不降级。
3. caller：`const caller = spec.parent`；`typeof caller?.id !== 'string'` 或 `ctx.agents?.get(caller.id) !== caller`
   ⇒ `{ok:false, code:'TEAM_NO_LIVE_CALLER', report}`（见 D4）。
4. 铸令牌（`deps.tokens.mint({taskId,role,seat,agentId:null,note:'team transport'})`）——与 subagent 通道同序。
5. 名字：`teamNameOf(...)`；`listMembers(caller)` 里同名已存在 ⇒ **复用**（不 spawn，见 D5）。
6. 正文：`const persona = rolePersona(role); const text = composeTeamBrief({brief: renderDispatchBrief(...), persona})`。
7. `await agentTeams.spawnTeammate(caller, {name, description, prompt:[{type:'text',text}], context:'fresh', provider:cfg.teamProvider||'spawn', signal: spec.signal ?? NEVER_ABORTED_SIGNAL})`
   → `member.id` 当 `agentId`/`sessionId`；`tokens.bindAgent(token, member.id)`。
8. 四槽：`applyPermissionSlot` / `applyModelSlot`（按 `member.id`）读回；`mode` 记 `UNAVAILABLE`（D3）。
   `teamStrictSlots` 且显式非默认槽钉不上 ⇒ `{ok:false}`。
9. `board.mirrorDispatch(env, task, {role, seat, memberName})`（best-effort，失败只 audit）。
10. 返回 `{ok:true, agentId, sessionId, token, via:'team', memberName, brief, slots, slotEvidence, note}`。
11. `TeamError` 翻译：`TEAM_MEMBER_LIMIT` / `TEAM_MEMBER_NAME_TAKEN` / `TEAM_LEAD_REQUIRED` /
    `TEAM_NOT_MEMBER` / `TEAM_INVALID_MEMBER_NAME` / `TEAM_MESSAGE_TOO_LARGE` → 可读 `report` + `escalate:'human'`。

**notifyRole 步骤**：
1. `stop === true` 且有 caller ⇒ `interrupt(caller, memberName)`，返回 `{ok:true, messageId:null, note:'已打断…'}`。
2. 目标解析：`spec.sessionId ?? spec.agentId` → `listMembers` 按 id 反查 name；找不到 ⇒ 退回
   `subagents.sendMessage(sender, agentId, [{type:'text',text}], {})`（既有行为），找不到 sender ⇒ 如实失败。
3. `sendMessage(caller, {target:name, content:[{type:'text',text}], signal})`；正文按 65536 字节截断（D7）。

## 4. 任务板镜像（`lib/team/board.js`）

- 落盘：`.pipeline/<任务>/team-board.json` = `{team_task_id, revision, last_action, at}`。
- `mirrorOpen(env, task)`：`createTask(caller, {subject:'[pipeline] '+task.id, description: requirement, writeScopes: 授权面路径})`
  → 记 revision=1。
- `mirrorDispatch(env, task, {role, seat, memberName})`：读 board state；`updateTask(caller, {taskId, expectedRevision: revision, action:'reassign', owner: memberName})`；
  冲突（`expectedRevision` 不符）⇒ 重读一次 revision 重试一次，仍失败只 audit。
- `mirrorClose(env, task, {reason})`：`updateTask(..., action:'complete')`。
- 全部 **best-effort**：任何异常 → `audit('team:board-error', {...})` + 返回值带 `note`；
  **不改变**流水线主流程的 `ok`。
- `env` 里没有 `agentTeams` 或 `config.teamBoard==='off'` ⇒ 直接 `{skipped:true, note}`（不抛）。

## 8. 实施偏差（Lead 已接受，写下来免得下次对不上）

1. **多拆了两个模块**：`lib/team/slots.js`（四槽补钉，91 行）与 `lib/team/deliver.js`
   （投递半边，147 行）。原因：`lib/transport/team.js` 一度 348 行，超「新文件 ≤300」约束。
   职责边界与 §1 一致，未越界改别人的文件。
2. **`reassign` 进了 spawn spec**：`dispatch.js` 的 `spawn:true` 分支加 `reassign: args.reassign === true`。
   02 §1.1 原签名没有它，但 01 §D5 要求"重派要换名" ⇒ 按代码真实形状补齐；其它通道不读，行为不变。
3. **令牌顺序调换**：原设计「先铸令牌再查名单」，实现改为「先查名单再决定复用/新建」。
   原因：复用既有 member 必须交回**它原来那枚**令牌（新令牌会被 `tokens.bindAgent` 的
   "一个会话同一任务只能一个角色"拒掉）。判据没变，理由写进了 `lib/transport/team.js` 注释。
4. **`slotEvidence.mode` 的字面值 `'UNAVAILABLE'`** 没进 `lib/transport/slot-evidence.js` 的词表
   （`EVIDENCE` 常量不在本批写入面）。若日后要统一词表，改那一处即可。
5. **任务板 env 有两条路**：派活镜像走 transport 显式 env（带活 Lead caller）；
   开单/关单走 `index.js` 的 `installBoardHost({ctx, config, dirs})` 晚绑定（没有活 caller，
   靠 `callerAgentId` 反查或 skipped）。两条都 best-effort。
6. **`auto` 优先级**：01 §D1 写「auto 保持 Session 优先」，02 又写了 `teamAuto:true` 先试 team ——
   两者不冲突：默认 `teamAuto:false` ⇒ 生产行为逐字不变；显式 `teamAuto:true` 才改序。
7. **本批发现的既有口径漂移（已在本批修掉）**：`tests/p11-presets-check.mjs` 判据⑦「与 shipped 预设逐字同形」
   在 DSH 0.2.1-rc.2 上会红 —— 官方 shipped 预设的 `@deepseek-ai/dsh-persona` 行不再写 `suffix`
   （只写 `complete` / `includeRuntimeContext` / `prefix`），而本插件的角色预设用 `suffix` 装尾部提示。
   `suffix` 仍是 `dsh-persona` 的**合法配置字段**（官方 README 配置表），所以是**测试判据过严**、
   不是预设写错。修法：`presets/plugin-schema.js` 增 `DOCUMENTED_EXTRA_CONFIG_KEYS`（只收有官方文档
   出处的键；目前只有 persona 的 `suffix`），判据改成「文档化字段不算发明」；
   反例 b（塞 `totallyMadeUp`）仍然判红，证明没有放宽成"什么都过"。
