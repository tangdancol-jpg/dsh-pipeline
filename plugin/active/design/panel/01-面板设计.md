# 自建面板 · 01 目标、契约与边界

> 本文件是**决策记录**：面板为什么这么切、数据长什么样、路由与落盘各自的判据在哪。
> 代码落点：宿主侧 `lib/panel/`、`lib/switch-routes.js`；客户端 `lib/client.js` + 18 个
> `lib/client.panel-*.js`。判据证据在 `tests/panel-snapshot-check.mjs` /
> `tests/panel-actions-check.mjs` / `tests/panel-ui-check.mjs` / `tests/panel-portal-check.mjs` /
> `tests/client-check.mjs`。

---

## 1. 目标与边界

面板要回答三件事：**这单走到哪了、谁在干、我现在能做什么**。所以它只做两件事：

| 做 | 不做 |
|---|---|
| **只读快照**：扫 `<项目根>/.pipeline/T-*/task.json`，压成任务 / 席位 / 待办计数 | 不改任务数据（快照里一个 `write*` 都没有） |
| **受控写动作**：终止 / 恢复 / 归档 / 删单 / 置顶 / 取消置顶 / 恢复归档 / 永久删除 | 不新造状态机判据（全部复用 `lib/states.js` 与 `store.transition` / `store.purgeTask`） |
| 把「能不能点」与「点了认不认」分成两处判据（快照只答前者） | 不读交接物正文、补丁、代码（面板不是代码浏览器） |

**不改宿主**。面板只用宿主已有的两条缝：

1. **HTTP**：`ctx.webServer.register({ kind: 'prefix', path: '/.dsh-pipeline', handler })` ——
   与开关共用同一个前缀，`/panel` 是新增的精确匹配路径，`/state` 的行为一个字没动。
2. **客户端 UI**：`ctx.slots.inject('conversation.session.header.utilities', …)` —— list 槽，
   两个条目（开关 order 100、面板 order 110）共用一次 inject，卸载时一起摘掉。

不装其它插件、不改 `dsh-client-ui-*`、不要求宿主新开槽位。

## 2. 数据契约

### 2.1 `GET /.dsh-pipeline/panel` 的响应

```jsonc
{
  "ok": true,
  "generated_at": "2026-10-18T05:00:00.000Z",
  "project_root": "<归一化后的项目根>",
  "tasks": [ /* 见 2.2 */ ],
  "warnings": ["任务 T-x：task.json 不是合法 JSON（…），已跳过。"]
}
```

- **绝不抛**：坏 JSON / 读失败 / 形状不对 ⇒ 跳过该任务并写进 `warnings[]`；连工作区目录都读不了
  才 `ok:false`（此时 `tasks` 为空、`error` 说清原因）。
- **目录不存在的语义是"空"不是"坏"**：还没跑过任何任务的 profile 返回 `ok:true, tasks:[]`。
- **只认 `T-` 前缀的目录**：`_memory` / `_trash` / 杂项一律不进主视图。

### 2.2 任务行：键序是契约

键序由 `lib/panel/task-fields.js` 的 `PANEL_TASK_KEY_ORDER` 固定（客户端按它渲染，测试逐字比对）：

| 序 | 键 | 类型 | 怎么算 |
|---|---|---|---|
| 1 | `id` | string | 目录名（`T-…`） |
| 2 | `state` | string | `task.state` 原值 |
| 3 | `state_label` | string | `lib/states.js` 的中文名；认不出就原样返回 id |
| 4 | `requirement_snippet` | string | 压缩空白 → 截 **80 个码点** → 超出加 `…`（按码点切，CJK / emoji 不会被劈开） |
| 5 | `updated_at` | ISO string | 盘上合法就原样用（与审计对得上），否则退回文件 mtime |
| 6 | `human_pending` | number | `human_requests[]` 里**还没答复**的条数（`relayed` 仍算待办；只有 `answered` / `withdrawn` 不算） |
| 7 | `team_board` | object \| null | 同目录 `team-board.json` 只读 `{ team_task_id, last_action }`；没有/读坏 ⇒ `null` |
| 8 | `seats` | array | 见 2.3 |
| 9 | `tier` | `"L0"`…`"L5"` \| null | **只从结构化字段读**（`roster.tier` 优先于 `task.tier`）；认不出就是 `null`，**绝不**从需求文本里猜 |
| 10 | `pinned` | boolean | 是否在 `_panel-pins.json` 的 id 表里 |
| 11 | `allowed_actions` | string[] | 见 2.4，**固定最后一个键** |

排序：**置顶优先**，组内按 `updated_at` 倒序，同刻按 id 升序（顺序确定性不靠天吃饭）。
置顶组内部**不另立**一套顺序：置顶只回答"要不要往上提"。

### 2.3 席位行（`seats[]`）

三层合并，顺序 = 显示顺序（`lib/panel/seats.js`）：

| 层 | 来源 | `status` |
|---|---|---|
| `main` | 恒一条：用户正在对话的那条会话 | `current` |
| `declared` | `roster.execution_roles`；`writer` 按 `roster.writers.partitions[]` 一个分区一位 | `declared` |
| `dispatched` | `task.dispatched[]` 里真派出去过的；同 (role, seat) **升级**并补会话 id | `dispatched` |

每行字段：`{ role, role_label, seat, status, kind, session_id, parent_session_id, member_name, layer }`。
`kind` 取 `session` / `team` / `unknown`（`manual` 通道没建会话 ⇒ `unknown`）。
真实台账里 `session_id` 常是 `null`、只有 `agent_id = "session-<uuid>"` ⇒ **显式 `session_id` 优先**，
取不到才剥前缀兜底（面板要靠它开会话）。

### 2.4 `allowed_actions`：只看状态机

固定顺序 `cancel, restore, archive, delete`，**只出现当前状态可用的**；判据全部来自
`lib/states.js`（`TERMINAL_STATES` + `findTransition`），本模块不另抄一份状态名单：

- `cancel`：先挡终态（迁移表那条是 `from:'*'`，对 `closed` / `cancelled` 也会命中）；
- `restore`：直接问 `unblock` 边；
- `archive` / `delete`：仅终态（与 `purgeTask` 同一份判据）。

`pin` / `unpin` / `unarchive` / `delete_archived` **不在**这个数组里：置顶与状态无关；
归档行的两个动作只对**归档视图**里的行成立 —— 列进来就会给在跑的单画出「恢复归档」按钮。

### 2.5 归档视图的行（`?view=archived`）

```jsonc
{ "ok": true, "tasks": [
  { "id": "T-…", "dir": "T-…-2026-10-18T060000Z", "state": "closed",
    "state_label": "已关闭", "requirement_snippet": "…", "archived_at": "…" }
], "warnings": [] }
```

`id` 是任务 id（右锚定剥掉 `-<stamp>`；剥不出来退回 `task.json.id`，再不行用目录名），
`dir` 是 `_trash` 下的真实目录名 —— **`unarchive` / `delete_archived` 的 `task_id` 收的是 `dir`**。

## 3. 路由（`lib/switch-routes.js`）

同一前缀 `/.dsh-pipeline` 下三条精确匹配：

| 路由 | 方法 | 行为 |
|---|---|---|
| `/.dsh-pipeline/panel` | `GET` / `HEAD` | 返回快照；其它方法 **405**「面板是只读的」；数据源没接线 **503** |
| `/.dsh-pipeline/panel?view=archived` | `GET` / `HEAD` | 只认 `view=archived` 这一个 query，走 `listArchived()`；**任何其它 query（含没有 query）走主快照** —— 归档数据源没接线时也先按主快照走，不拿主快照冒充归档 |
| `/.dsh-pipeline/panel/action` | `POST` | 写动作入口；执行器没接线 **503**；JSON 解析失败 / 不是对象 **400**；请求体超限 **413**；执行器抛异常 **500**（并且**不**把异常文本回给客户端） |

三道闸，缺一不可：

1. **环回**：非环回 `remoteAddress` 一律 **403**（面板能读全项目状态，不做公网面）。
2. **开关门**（在 `lib/panel/actions.js` 里，**只有一份**）：开关关着 ⇒ 8 个动作全部拒，
   并且**一个字节都不写**（不去读盘、不碰 pins / archive）。
3. **跨站闸**（只对 `POST`）：只收 `content-type: application/json`（挡掉免预检的表单 /
   `text/plain`），`Sec-Fetch-Site` 只认 `same-origin` / `none`，带了 `Origin` 就必须与 `Host`
   同源（`Origin: null` 也拒）；动作请求体上限 **8192 字节**（超了 413）。客户端 UI 走同源相对 fetch，
   本来就发 JSON，不受影响。

**路由层不判动作白名单**：`pin` / `unarchive` 等新动作原样递参给执行器 —— 白名单、开关、
二次确认都在 `lib/panel/actions.js` 一处，路由层再判一遍就是第二份会漂移的判据。

## 4. 存储：三个文件，各只有一个写者

| 文件 | 写者 | 语义 |
|---|---|---|
| `<项目根>/<工作区目录>/_panel-pins.json` | `lib/panel/pins.js` | 置顶 id 表：`{ version: 1, ids: [...] }`，上限 **200**；**原子写**（`tmp` + rename）；坏文件当空表，**不抛**；id 是不透明字符串，任务删了也留着（无害） |
| `<项目根>/<工作区目录>/_trash/<任务id>-<时刻>/` | `store.purgeTask(mode:"trash")` | 归档目录（`archive` 动作 = 留档）；恢复用 `renameSync` 挪回主视图，两道硬闸：必须是 `_trash` 的**直接子目录**、目标目录**不存在**（挡覆盖在跑的单） |
| `<项目根>/<工作区目录>/_purge-log.jsonl` | `store/purge.js`（`delete` / `delete_archived` 共用） | 永久删除的墓碑账本；**先留痕、后动手**，账本不在被删目录里，所以删完还查得到 |

**置顶为什么落在工作区**：跟着 profile 走，不散落在机器别处；而且它**不是状态变更**，
`task.json` 一个字节都不该动 —— 否则"只读快照"这条边界就破了。

**归档的目录名为什么右锚定拆**：`<任务id>-<stamp>`，任务 id 自己就带短横线
（`T-20261015-bb30bc`），只能从右边认 `-2026-10-18T042252Z` 这个时刻尾巴。

## 5. 客户端：入口 375 行 + 18 个 chunk，弹层走 portal

- **入口** `lib/client.js`（375 行）只做三件事：注册模块（`__ModuleLoader__.load`）、
  「多AI 协调」开关、「多AI协调团队」面板的 **lazy wrapper**（首次渲染才取 chunk）。
- **18 个 chunk**（`lib/client.panel-*.js`；入口 + chunk 共 19 个文件、合计 4743 行；每个
  120–350 行为宜、硬上限 400、**不得落在 390–400**）：`view`（388，纯渲染）、`menu`（335，
  ⋯ 菜单 / 置顶）、`shell`（320，骨架与组装）、`actions`（297，动作契约）、`preview`（296，
  预览底料）、`atoms`（294，内容原子）、`preview-control`（281，预览状态机）、`portal`（249，
  弹层容器与出口）、`batch`（240，批量状态机）、`interact`（223，交互 glue）、`batch-bar`（206，
  底部批量栏）、`preview-bubble`（201，预览浮层）、`seats`（198，席位格）、`outside`（196，
  点外面 / ESC 判据）、`preview-data`（180，预览取数与几何）、`poll`（168，轮询 / 取数）、
  `card-actions`（167，卡片动作执行）、`controls`（129，可点小控件）。
- **加载协议**：入口 `Promise.all` 逐个 `require.async('./client.<name>.js')` → 交给 `shell` 按依赖序
  `create(deps)` 组装；宿主按 `/plugins/dsh-pipeline/<chunk>?rev=<入口 rev>` 提供并 **immutable**
  缓存；chunk 是经典脚本、必须与入口同目录、彼此**不能**同步 `require`。
- **共享作用域 `S`**：`shell.createPanel` 里造一份状态与方法（`open` / `view` / `snap` / `readOnce` /
  `renderPreview` …），各 chunk 通过 `create(deps)` 拿到自己那一份依赖，**不**互相 `require`。
- **弹层 portal（为什么挂 body）**：宿主会话头部是**窗口拖拽区**，又有自己的层叠顺序与命中区 ——
  弹层只要还长在它的 DOM 里，点击就可能被吃掉。所以 ⋯ 菜单与预览浮层用
  `ReactDOM.createPortal(children, document.body)` + `position:fixed` 渲染：
  - **落点公式**：`right = 视口宽 − rect.right`（与触发按钮右缘对齐，收边不小于 8）、
    `top = rect.bottom + 6`（原来外层 `paddingTop` 撑出的缝）、`width = min(440, 92vw)`、
    `maxHeight = min(560, 70vh)`，`top` 再按视口底部收一次。
  - **滚动 / 改尺寸重算**：监听 `scroll` / `resize`，100ms 节流重算；拿不到 `window` 时按 1280×800
    兜底，只求不炸。
  - **点外面判据**：`ref.contains` 会因 ref 脱手失真 ⇒ 再按 DOM 属性
    `target.closest('[data-pipeline-panel]')` / `[data-pipeline-panel-root]` /
    `[data-pipeline-seat-preview]` 复核；判不出来（`null`）**不关** —— 宁可漏关一次，不误关正在用的面板。
  - **回退**：取不到 `react-dom`（自测桩 / 老宿主）或没有 `document.body` ⇒ 一律回退成原样渲染，
    不把面板弄挂。
- **预览取数**：`sessions.retain(sessionId, { source: 'gateway' })` → `ref.ready` → `binding.eventSource`
  → `getSnapshot().entries`，读完**立刻释放**引用（最多同时留 3 个，6 秒超时，30 秒缓存）。
  只显示真实用户 / AI 文本：过滤注入的系统上下文（`Current runtime context` / `Time sampled` /
  `<system-reminder>` …）与工具行；AI 还没吐正文 ⇒ `thinking: true`，渲染成斜体灰字「正在思考…」；
  单行超长截到 200 字符，最多 12 行。
- **点气泡打开会话**：与点席位名字同一条路径 —— `resolveUiWorkspace(ctx)` + `workspace.openSession(...)`
  （team 通道的队员按 `{ parentSessionId, childSessionId, mode: 'continuable' }` 打开）。
  `uiWorkspace` 拿不到时面板只显示一行人话错误，不影响开关与其它功能。

## 7. 还没验到的（如实列出）

- **真实浏览器排版**：桩 React 只能验"渲染出什么元素 / 点了会发什么请求"，验不了像素位置、
  与宿主主题字体的协调，也验不了 portal 弹层在真实 Electron 里的层叠与命中顺序、像素落点。
  组件用纯内联样式、不读宿主 CSS 变量 ⇒ 「长得不好看」的风险大于「不显示」的风险。
- **真机点击链路**：装在真实 profile 后从「悬停 → 预览取数 → 点气泡 → 打开会话」的整条链路，
  以及 `uiWorkspace` 在真实宿主里的形态，都还没有真机记录。
- **归档视图的真实目录**：单测里 `_trash` 是临时目录造的；真实项目里被 `purgeTask` 收掉的
  目录名是否都符合右锚定规则，需要在有归档数据的 profile 上抽查。
