### 1. 检测"被切断" —— 与既有判词**分得开**（四种判词）

- **怎么实现**：新模块 `lib/orphan.js`，判据是**纯函数**（不读盘、不写盘、不抛）：

### 5. 不刷屏 / 不变成新的静默源

- **需求原话**：「同一单同一条原因不得反复播报（幂等账本已有，复用它）」「不得刷屏 / 不得变成新的静默源」。

- **怎么实现**（复用的都是**既有**账本 API，没有新开账本）：
  1. **身份内容派生**：`<任务>|orphan|<判词>|<状态>|<最后一次进展时刻>` —— 同一次卡死跨多轮是**同一个键**；进展恢复后再卡住 ⇒ 时刻变 ⇒ **新的一条**（不会永久哑掉）。
  2. **成功即记账**：`ledger.record(key)` ⇒ `hasDelivered` 命中 ⇒ 同一条**永不重投**（只记 `skip`，不写审计、不播报）。
  3. **失败限次 + 退避**：失败次数**从账本里数**（`unresolvedEntries` ⇒ 跨进程有效，不新开计数器），两次之间至少隔 `orphanRedeliverBackoffMs`（默认 30 分钟），到 `orphanMaxRedeliverAttempts`（默认 3）次记 `markEscalated` = 放弃。
  4. 每条身份最多**一条**给席位的消息 + 最多**一条**给主对话的播报（成功 / 放弃各一条；失败走既有巡检那条，天然按"新的一条 unresolved"计一次）。

- **验证**（实际输出）：
  ```
  ✓ ★★ **幂等**：账本里记下这条身份；**同一身份再扫两轮 ⇒ 仍然识别得到，但一次都不再投、不再播**
      账本 hasDelivered=true 第二轮 orphans=1/动作=skip 第三轮 orphans=1/动作=skip
      notify 次数=1（应恒为 1） 播报=1（应恒为 1）
      理由：这一条孤儿身份**已经成功重投过**（账本里有键）—— 同一条不重投。
  ✓ ★ 放弃之后**彻底停下**（同一身份不再尝试、不再播报、不再记 unresolved）
      第四轮 动作=skip 本轮发起=0 notify 次数=2（恒为 2） unresolved=2（恒为 2）
  ```
  ★ 诚实说明：**"识别"与"动手"是两件事** —— 已处理过的身份每轮仍会被"识别到"（`orphans=1`），但 `new_orphans=0`、一个字节都不投、一条都不播。只读面把这两个数**分开报**，不含糊。

**巡检能不能直接覆盖本条？—— 不能，而且是**判据层**的不能**（这是本单最重要的一次判断，写在代码注释里）：
- 巡检是**只播报、不动作**，这是用户裁定 A22 写死的（`lib/patrol.js` 文件头 + `index.js` 3.3 段注释），把它改成"会动作"就是动一条既有裁定；
