## 【这个日志怎么用】

- **谁写**：**归档位（archivist）**。本日志、以及需求单 `需求清单与进度-20261014\需求清单与进度.md` 与 `bug待修复单-20261014.md` 两份文档的维护职责，**都在归档位**；主对话不再自己维护这两份文档。
- **什么时候写**：每一次**实际变动**之后 —— 编写交付 / 修复落地 / 测试通过 / 被打回 / 计划变更 / 制度变更。**没有实际变动就不写**；**不许编造**（写不出证据的条目，就是没发生）。
- **每条必写五样**：**时间** · **谁（角色/席位）** · **哪个单（单号，或「非单」）** · **变了什么** · **证据**。
- **证据字段的要求（★ 硬要求）**：**必须能回到实物** —— 报告文件名（带字节数）/ 交接物 id / 制品版本 / 审计动作名 / 账本行 / 测试套件名与通过数。
  只写「已完成」「已修复」「已验收」**不算证据**；读者照证据**应该能自己核一遍**。
- **拿不准的怎么写**：谁做的若报告里没署名会话，就写「未标注」—— **不许猜**一个会话名或单号填进去。
- **时间怎么取**：「时间」= 该条证据（报告/文件）**落盘的时刻**（可核）；若报告里写了代码落地时刻，在「变了什么」里另行注明。
- **行格式（机器可读，改动会打断面板解析）**：
  `- [YYYY-MM-DD HH:mm] 谁：…｜单：…｜变动：…｜证据：…`
  （分隔符**全角 `｜` 或半角 `|` 都认**，字段名前后可有空格；**五个字段名本身不要改**。）
