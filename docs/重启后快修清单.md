## ④ `notify_only` 传话通道【每次必崩】—— 有精确行号，最好修
- **现象**：`pipeline_dispatch { notify_only: true, role, seat, task_id }` 直接抛内部错误
- **原文**：`ReferenceError: Cannot access 'seat' before initialization`
- **落点**：`lib/tools.js:1760:49`（`at Object.run`）
- **原因**：`seat` 在其 let/const 声明**之前**被引用（暂时性死区）
- **为什么最要紧**：这是"机制主动找到**已存在**的席位并投递"的唯一代码路径 —— 也就是"叫醒既有席位"的正解。它崩 ⇒ 只能重派新席位
- **修法**：把 `seat` 的取值/解析移到使用之前；或改用已解析好的席位键
- **验证**：同一条 `notify_only` 调用不再崩，且真的投进**既有**席位会话（不新建会话、不改状态）

## ③ `auto_geometry` 目标字号 >8px 一律误判「无解」
- **现象**：`diagram_deliver { auto_geometry: true, geometry_target_px: 10 / 11 }` → 拒「无解（font-below-target）」
- **原因**：把渲染器里**写死的 8px 边标签字号**当成了"投影字号天花板"；而**画布比舞台窄时缩放是放大的**，该前提不成立
- **修法**：目标字号的判据对齐"实际投影字号 = 8px × 缩放比"，或至少放开 >8 的取值
- **附带**：`diagram_deliver` 不传 `auto_geometry` 时会崩 `Error: g.rounds is not iterable`（同一处未初始化）
