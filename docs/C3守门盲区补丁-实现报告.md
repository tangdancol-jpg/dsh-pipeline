## 一、盲区怎么来的

### 1. F 路刚做的改动（指引原文，逐字引用）

| 落点 | 文件:行 | 原文 |
|---|---|---|
| system prompt 段 | `index.js:1016-1022` | 「多行命令，或命令里带引号 / 反斜杠 / 中文 / 换行时，**不要**整段塞进 shell 的 command 参数 —— 先把脚本落到**你有权写的位置**，再执行那个文件（`pwsh -File x.ps1` / `bash x.sh`）」…「★ 它是**写法**，不是后门：落盘的脚本与直接写在 command 里的命令，受**同一套判据**管」 |
| 席位开场简报 | `lib/intercept.js:254-258` | 「★ 要跑 shell 时：多行 / 带引号 / 带中文 / 带反斜杠的命令，**先落盘成脚本文件再执行那个文件**（`pwsh -File x.ps1` / `bash x.sh`），不要整段塞进 command 参数。」…「它是写法不是后门：脚本与命令受**同一套判据**管」 |

F 路的**理由是对的**：多层转义会把工具调用的 JSON 写坏 ⇒ `MALFORMED_RESPONSE` ⇒ **整轮作废**（含此前全部上下文），那是最贵的一种 token 浪费。

### 2. 但这会打开一个守门盲区（C3）

「受同一套判据管」在改前**不成立**。现判据的位置与形态：

```
lib/guard.js:1094   if (isShellToolName(name, cfg) && binding !== null) {     ← shell 旁路入口
lib/guard.js:1097     const commands = collectCommandStrings(args)            ← 只收【命令行字符串】
lib/guard.js:1098     for (const cmd of commands) {
lib/guard.js:1099       const m = scanShellCommand(cmd, task, binding.role, cfg)   ← 只扫这些字符串
lib/guard.js:1100       if (m !== null) return m
lib/guard.js:1101     }
```

`collectCommandStrings`（`lib/guard.js:412-436`，均为**改前**行号）收的是 `args.command / cmd / script / input / code / shell_command` **这几个字符串字段本身**。

⇒ 命令一旦写成 `bash build.sh`，守门看到的是 13 个字符的 `bash build.sh`；
**`build.sh` 的正文里写了什么，守门一个字节都看不到**。
⇒ 「把 `npm test` 写进 `build.sh`，再 `bash build.sh`」这种写法，
改前 `scanShellCommand` 的**全部**判据（编写不跑测试 / 测试审核不改代码 / 控制角色不读代码 / 最小改动）**一起失效**。

这正是 F 路那条指引会把**正常用法**推向的形态 —— 不是有人恶意绕，而是**照着指引做就绕过去了**。

## 二、展开函数设计

### 设计原则：只加展开，不放宽

新增一层**展开**，把「命令里确实被执行的那个脚本」的正文读出来，喂回**同一个** `scanShellCommand`。
既有判据的阈值 / 名单 / 语义**一个字节都没改**（见 §五 的加法性证明）。

### 1. 展开哪些命令形态（从实际会出现的形态里挑，不穷举）

| 形态 | 例子 | 识别方式 |
|---|---|---|
| js 运行时 | `node x.mjs` · `deno x.ts` · `bun x.js` · `tsx x.ts` | 先定位解释器词，再到**同一个命令段**里挑脚本 token |
| POSIX shell | `bash x.sh` · `sh ./x` · `zsh x.zsh` | 同上 |
| PowerShell | `pwsh -File x.ps1` · `powershell.exe -File .\x.ps1` | 认显式 `-File` 开关 |
| cmd | `cmd /c x.bat` | 认显式 `/c` |
| 直接执行 | `./x.sh` · `.\x.ps1` | 边界只认行首/空白/`;&|` |

**刻意不碰**：`-c` / `-Command` / `-e` 那几种**不是脚本文件** —— 命令正文本来就在命令行字符串里，
既有扫描器照旧看得到；把它们当成"脚本"去展开只会制造噪音。

**实现要点（踩过的坑）**：不用一条大正则去"跳过若干开关再抓 token"。
`pwsh -NoProfile -ExecutionPolicy Bypass -File "C:\a b\x.ps1"` 里 `Bypass` 是**两段式开关的第二段**，
`(?:-\S+\s+)*` 这种写法会在它上面回溯失败、静默漏掉。改成**两段式**：
先 `RE_SCRIPT_INTERP` 定位解释器 → `scriptSegmentOf()` 切出同一个命令段（到 `;` `&` `|` 换行为止）
→ `scriptTokensOf()` 按"成对引号优先"切 token → 再挑。`-File` / `/c` 走**锚点**（找开关再取下一个 token）。

### 2. 深度上限

```
SCRIPT_EXPAND_MAX_DEPTH = 1      // 命令行 → 脚本（depth=1）
SCRIPT_EXPAND_MAX_FILES = 4      // 单条命令最多展开 4 个脚本
SCRIPT_EXPAND_MAX_BYTES = 64KB   // 每个文件最多读头部 64KB
SCRIPT_EXPAND_MAX_TRACE = 8      // 每类痕迹最多 8 条
```

**为什么封顶 1 层**：展开是**树的遍历**。不封顶 = 一次工具调用可以触发无界的文件读取，
守门自己就变成了开销源与递归风险的来源。1 层正好覆盖本次盲区的实际形态
（F 路的指引是把**一条命令**落盘成**一个**脚本）。

**到顶了要报出来**（这是要求里明确的一条）：脚本 A 内部又出现脚本执行形态时，
**不再展开 B，但把 B 记进 `capped` 痕迹**，通过导出的只读接口 `lastScriptExpansion()` 取出来看：

```json
[{"raw":"b.sh","path":"…/proj/b.sh","from":"…/proj/a.sh","depth":2,"limit":1,"exists":true}]
```

`exists:true` 说明"这里本来还能再展开一层、而且那个文件真的在" —— 不是空引用。
它**不改判据**（不因为到顶就拒，否则任何"脚本调脚本"的正常用法都会红），
所以只能靠这份痕迹"报出来"，而不是静默过去。

### 3. 读不到的口径（★ 三条分开，依据写在这里）

| 情况 | 处置 | 依据 |
|---|---|---|
| 字符串不像路径（带引号残渣 / `(` `)` `=` `$` `!`）、文件**不存在**、**不是普通文件**、扩展名不在 `SCRIPT_EXTS` | **跳过**，记 `missing` / `not-a-file` / `ext` / `unresolvable` | **没法藏东西**：藏东西的前提是文件真的在、真的是个脚本。此处一律拒会误拦正常脚本（例如脚本由上一步刚生成、或路径按别的 cwd 解析），而要求里写了"**不许误拦正常脚本**"。 |
| 文件**存在却读不出**（权限 / 句柄被独占 / 打开失败） | **拒**（fail-closed），记 `unreadable` | 这就是既有口径里的"**扫描不到 ⇒ 不放过**"：能藏却读不到，就没有理由放它过去。**误拦风险≈0** —— 文件被独占/无权限时，那条命令本身也执行不了。 |
| **太大**（> 64KB） | **不拒**，只读**头部 64KB** 再扫，记 `truncated` | 按体积**拒**会误拦正常的大脚本；按体积**跳过**会开一个"把违禁命令放在 64KB 之后"的洞。**读头部是唯一两边都不吃亏的处置**。 |

补充一条诚实口径：**展开器自身抛异常**时降级为"改前行为"（既有判据已经先跑过并给过答案，不会被展开器改写），
痕迹里记 `threw`。这与上表第 2 行不矛盾 —— 那行说的是"脚本文件读不出来"（可判定、且能藏东西），
这行说的是"展开器自己出错"（不可判定）。一律拒会让整个 shell 通道全红，那是拿一个大 bug 换一个小洞。

### 4. 不自我递归 / 不当"读任意文件"的通道

- **只读确实被执行的那个脚本**：只认 §1 表里那几种**执行**形态；`require("./x.js")` 里的字符串字面量不是"被执行"（直接执行形态的边界刻意**不含引号与 `(`**）。
- **只读脚本扩展名**（`SCRIPT_EXTS`，27 个）：`node package.json` / `bash ./data.txt` 一律不读。
- **正文只用于匹配、从不回显**：拒绝文案里只有命令片段，没有正文 —— 守门不会被当成读文件的通道。
- **守门自己这一族文件绝不展开**（`GUARD_SELF_FILES` = 从 `import.meta.url` 推出来的 `guard.js` / `guard-factory.js` / `hashgate.js`）：命中记 `self`。
- **重入标志** `SCRIPT_EXPAND_BUSY`：展开期间的重入直接返回空痕迹（配合深度上限构成双保险，`try/finally` 保证一定能复位）。

## 八、★ 我仍然拦不住的（如实列）

1. **★ 违禁命令放在脚本第 64KB 之后** —— 只读头部，扫不到就放行。
   （反例①-c 第 4 条**就是**这条缺口的实测：`huge-tail.sh` 放行了。）
   为什么明知有洞还这么定：按体积拒会误拦正常大脚本，按体积跳过就等于完全不读。
   要堵这条得改成流式扫描 + 上限时间预算 —— 那是另一个量级的复杂度，本轮没做。
2. **★ 脚本套脚本（A → B）只到第一层** —— `a.sh` 里写 `bash b.sh`，B 里写什么都不看。
   反例② 实测放行。痕迹里有 `capped`，但**痕迹不是拦截**。
   深度每加一层，开销与递归风险都上一个台阶，所以停在 1 层并且**明说**。
3. **非脚本扩展名的脚本**：`bash ./payload.txt` / `node ./x.dat` —— 扩展名不在 `SCRIPT_EXTS` 里就**不读**。
   （`bash data.txt` 这种没带分隔符的更是连"像路径"都过不了。）这是为了不把守门变成"读任意文件"的通道而付的代价。
4. **整串被引号包住的内嵌命令里的脚本**：`pwsh -Command "node x.mjs"` 里那个 `x.mjs` 不会被展开
   （token 里带空格 ⇒ 不当路径）。**但外层命令串本身照旧被既有扫描器扫**，所以只丢"脚本正文"这一层。
5. **解释器用绝对路径且名字在长路径段里**：`/usr/bin/sh` 认得出，但
   `node_modules/.bin/tsx` 这类要靠 `RE_SCRIPT_INTERP` 的边界命中，**没有做 PATH 解析** —— 认不出的解释器就不展开。
6. **变量拼接 / 间接执行**：`F=$(ls *.sh); bash $F`、`bash "$(cat which.txt)"`、
   `eval "$(cat cmd.txt)"`、`chmod +x x && ./x`（`chmod` 那条命令里没有 `./x` 的执行形态）——
   这些**本来就在 README 的「哪些是约定」里写着"shell 侧是 best-effort，不是保证"**，本补丁没有改变这个定性。
7. **把违禁内容编码后再在脚本里解码**：`echo bnBtIHRlc3Q= | base64 -d | sh` —— 脚本正文里是 base64，
   扫描器看到的只是 base64 字符串。**编码绕过是这条补丁结构性拦不住的**（既有判据也是字符串匹配）。
8. **展开器自身抛异常时降级为改前行为**（§二.3 末段）：这种情况下脚本正文不参与判定。
   痕迹里记 `threw`，但**没有人会去看痕迹** —— 这是一个"静默降级"，我把它写在这里而不是假装它不存在。
9. **守门自己这一族文件（`guard.js` / `guard-factory.js` / `hashgate.js`）刻意不展开**
   ⇒ 把违禁内容写进这三个文件再执行，不会被展开扫到。（`self` 护栏的代价；
   实际上没人会去执行它们，但**这也是一个洞**，一并列出。）
10. **`cfg.guardScriptBodies` 开关进不了配置表**（§三），只能改代码关 —— 也就是说**用户当前没有办法从配置上关掉这条新判据**。
