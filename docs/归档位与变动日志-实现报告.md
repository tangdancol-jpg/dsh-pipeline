## 一、变动日志怎么设计的（字段与证据要求）

### 1.1 文件本身

| 项 | 值 |
| --- | --- |
| 路径 | `<DSH_HOME>\dsh_orb\变动日志.md` |
| 形态 | **Markdown · append-only**（只追加；面板只读渲染，**没有任何写入接口**） |
| 编码 | UTF-8 无 BOM、LF 换行（与两份文档一致） |
| 建时/现况 | 新建 → **10,977 B** · sha256 `145218cb517dc275…` · **12 条** |

### 1.2 每条记什么（五样，缺一条就不算合格的日志行）

**时间 · 谁（角色/席位）· 哪个单（单号或「非单」）· 变了什么 · 证据**

### 1.3 ★ 证据字段的要求（这是这份日志的"防伪面"）

**必须能回到实物** —— 只允许这几类取值：

- **报告文件名**（带字节数，如 `A路-终态过滤包-实现报告.md`（39,132 B））
- **交接物 id / 制品版本**（如 `H-…`、`v1`/`v2`、`<session-id>`）
- **审计动作名 / 账本行**（如 `orphan:redeliver-abandoned`、`wake-ledger.jsonl` 第 47 行）
- **测试套件名与通过数**（如 `tests/wake-channel-check.mjs 60/60`）
- **可核的盘上事实**（文件字节数 + sha256、进程 pid、备份文件名）

**明确不算证据**：「已完成」「已修复」「已验收」这类自述。
**拿不准怎么办**：报告没署名会话的，就写「**未标注**」——**不许猜一个会话名或单号填进去**（本次 12 条里有 4 条是「未标注」，都是报告本身没署名的情况）。

### 1.4 行格式（机器可读，人在页面外也能一眼看懂）

```
- [YYYY-MM-DD HH:mm] 谁：…｜单：…｜变动：…｜证据：…
```

- 分隔符 **全角 `｜` 或半角 `|` 都认**，字段名前后可有空格（人力追加时不该被形状卡住）；
- **五个字段名不要改**（面板按字段名取值）；
- 解析**不放宽到"猜"**：形状坏掉的行**不会被静默吞掉**，面板会显示「**形状坏掉 N 行**」（本次实测过，见第五节 ⑤）。

### 1.5 「时间」怎么取（口径写在日志顶部）

「时间」= **该条证据（报告/文件）落盘的时刻**（可核）；报告里若写了代码落地时刻，在「变了什么」里另行注明。
日志顶部另有一段**【这个日志怎么用】**：谁写 / 什么时候写 / 五样字段 / 证据要求 / 拿不准写「未标注」/ 行格式 —— 面板会把这段一起渲染出来。

## 附二：过程中发现并修掉的两个解析缺陷（如实登记）

1. **第三处分隔符落成半角 `|`**：日志首版三个分隔符里有一个是半角，严格正则解析为 **0 条**（面板栏是空的）。
   → 处置：把文件里的分隔符统一成全角 `｜`，**并把解析器改成两种分隔符都认**（人手工追加不该被形状卡住）。
2. **分隔符后多了一个空格**（`｜ 证据：`）：同样导致 0 条。
   → 处置：字段名前后允许空格；文件里的多余空格一并清掉；**格式说明里写明这两种容差**。
