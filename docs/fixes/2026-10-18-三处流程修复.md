# 三处流程修复（2026-10-18）

> 这一批修复来自一张 L5 长单的实测反馈：三处判据缺口让"该能跑通的流程"卡住。
> 本文只写**修了什么、修前是什么样、怎么验证**；完整的问题清单与后续项在仓库里不公开（内部留档）。

## 1. 计划必须"授权面有主"才允许分配（`pipeline_plan`）

**修前**：`change_scope` 里可以写一堆路径，而 `writers.partitions[].scope_paths` 只覆盖其中一部分。
守门要求"分区 owner + change_scope 同时命中"才能写，于是没被分区覆盖的那几条路径
**任何编写席位都写不进去**；更麻烦的是计划提交后状态已推进，`pipeline_plan` 只能在「计划中」提交，
中途无法回修 —— 授权面里的书面交付物只能永远缺位。

**修后**：分配 AI 之前逐条校验：

- 每条 `change_scope` 必须**要么**落在某个编写分区的 `scope_paths` 路径内（判据与守门同源，复用 `owningSeat`）；
- **要么**显式写 `owner_role: "<角色>"`，且该角色必须是 `writes: 'workdir'`（真的写得了这条路径）；
  `docs` / `release` 这类只能写自己报告目录的角色会被拒，避免"看着有主、实际写不了"的假出口。
- 不满足 ⇒ **不分配 AI**，一次列出所有没主的路径 + 现有分区范围 + 两条出路（补分区 / 加 `owner_role`）。

**验证**：`tests/plan-check.mjs` 新增反例⑥（有路径没分区 ⇒ 拒）与反例⑦（`owner_role: docs` ⇒ 拒）；
6 层夹具同步补齐授权面（原夹具本身就是"授权面与分区不一致"的形状）。

## 2. 重派席位时吊销旧令牌（`pipeline_dispatch { reassign: true }`）

**修前**：`reassign:true` 会派一个新会话，但**旧会话的令牌还在**，旧会话仍在活动时两个席位
可能同时写同一目录（实测两个 tester 同时写 `reports/tester/`，结果属于哪个会话说不清）。

**修后**：派新席位**之前**先撤销旧席位令牌；旧会话之后的任何写操作都会被守门以"没有身份"拒掉。
回执里明写"已吊销旧席位令牌"，不假装旧会话会自己退出。

**验证**：`tests/liveness-check.mjs` E5 新增断言：重派后 `tokens.roleOfAgent(旧 agent_id) === null`，
且新令牌可用。

## 3. 关单缺口一次列全 + 预演（`pipeline_close`）

**修前**：关单前置条件按顺序判、遇到第一个缺口就返回。主对话被连拒 3 次（缺安全结论 →
缺架构图 → 缺发布/文档/性能产物），每次都要新派一个席位等 3–10 分钟。

**修后**：

- 关单闸门的清单抽成模块常量，`store.closeGaps(task)` 把每一道闸都跑一遍、**不早退**；
- `pipeline_close` 失败时自动附**完整缺口清单**（逐项 code + 首行原因 + 补法提示）；
- 新增 `dry_run: true`：只预演、不改状态、不写 `close_report`。

**验证**：`tests/f18-close-after-passed-check.mjs` ⑬-D：缺口 ≥3 项、`dry_run` 摘要含「完整缺口清单」、
预演后状态仍 `passed` 且无 `close_report`。

## 第二批（同一天完成）：P0-2 / P1-9 / P1-4

### 4. 浏览器 Profile / 凭证类数据不得进入工作区（P0-2）

- **修前**：测试席位为跑真机用例，可以把浏览器 profile 目录复制进工作区（里面有 Cookies / 登录数据 /
  本地状态等真实隐私数据）；安全扫描只把它当成普通路径，没有"凭证落盘"这个一等类别。
- **修后**：新增统一的"凭证 / 浏览器 profile 路径"识别（文件名 + `*.sqlite` + profile 目录段，守门与
  扫描器共用一份名单）；写类工具与 shell 复制/写入命中即拒，文案给「脱敏夹具 / 临时空 profile」的
  可操作替代；`pipeline_security_check` 新增「凭证落盘」面（计入 finding、不能给 clean），
  且 profile 目录命中即记录、不再下钻读取隐私数据。
- **验证**：`tests/f24-browser-profile-guard-check.mjs` 33/33；`security-check` 36/36 不回归。

### 5. 并行席位的哈希闸门归属误报（P1-9）

- **修前**：哈希闸门用"基线以来的全部变化"去对**本席**的声明 ⇒ writer#1 早写进工作区的文件，
  成了 writer#2 的"未声明改动"；连续误报会触发"连续 3 次交人工"。
- **修后**：`dev_to_test` 支持一次显式归属确认 `foreign_paths_ack: [{ path, reason }]`：
  只能确认"本次确有变化、不属于本席、位于**另一个在册编写席位**分区、且不是越界改动"的路径；
  ack 不能洗自己的改动、不能洗越界、不能提前买保险、删除类不适用；确认逐条进审计与 counts。
  没写 ack 的提交走到的判据与改前逐字节相同。
- **验证**：`tests/f25-hashgate-attribution-check.mjs` 25/25；f16 / f17 / hashgate-check 不回归。

### 6. 席位"在等审批"不再被误判失联（P1-4）

- **修前**：`ask` 审批策略下，席位弹出审批卡等人点时静默数分钟，被判"失联"，主对话据此重派，
  白白浪费一轮。
- **修后**：liveness 增加 `awaiting_approval` 分类——从会话事件里精确识别"`approval/asked` 没有配对的
  `approval/decided`"，这类席位**不冻结、不改状态**；`pipeline_status` 显示「⏳ 席位在等审批 ——
  不是失联」「在等你批准 N 个工具调用」，并提示去点审批卡、不要重派。
  反例一个字没放宽：真死 / 读不到 / 读到了没在等 ⇒ 照旧判失联并冻结。
- **验证**：`tests/f26-liveness-approval-check.mjs` 40/40；`liveness-check` 45/45 不回归。

## 第三批（同日完成）：P2 池

### 7. `pipeline_wait`：别用 sleep 轮询

- **修前**：主对话只能 `pipeline_status` + `sleep` 反复轮询（实测一张单 sleep 40+ 次，token 消耗大头）。
- **修后**：新增 `pipeline_wait { task_id, until_state?, until_event?, timeout_ms?, interval_ms? }`：
  只读长轮询，条件（状态 / 历史动作，或关系）满足立刻返回；超时返回当前状态 + 最近动作 + 建议；
  非法参数 0ms 拒绝；不发请求、不写盘、不改任务状态。
- **验证**：`tests/f27-pipeline-wait-check.mjs` 43/43；工具总数 36→37（load-smoke 的精确计数同步）。

### 8. P2 四处小修

- `pipeline_human_relay` 的"照抄块"改用真实换行（请求正文里误存的字面 `\n` 只在展示层还原，存盘不改）；
- `pipeline_demo confirm` 的必填参数（`round_index` / `human_request_id`）写进参数描述与速查，并修正闸门提示里的参数名；
- `pipeline_status` 的 `fields` 未知键时返回可用键清单 + 提示（`_available_fields` / `_hint`），
  `task.json` 超过 1 MiB 时提示改用 `detail=summary` / `fields`；
- 两条被拒文案补"允许的替代形态"（内联 `node --check -e`、只读命令、用 write/edit 写文件）——判据未动。
- **验证**：`tests/f28-p2-polish-check.mjs` 27/27。
