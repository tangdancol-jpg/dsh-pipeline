## 二、轮换动作

### 1. 怎么生成新的四把

用**面板自己的机制**：

```
cd %USERPROFILE%\.dsh\dsh_orb\dashboard
node server.mjs --init
```

它内部 `newKey() = crypto.randomBytes(16).toString('hex')` ⇒ 32 位十六进制；`ROLES = [main, orchestrator, supervisor, archivist]` ⇒ 正好四把。输出（面板自己就只打掩码）：

```
[控制面板] 已生成 %USERPROFILE%\.dsh\dsh_orb\dashboard-keys.json
  端口      18240（已探测为空闲）
  权限      chmod 600 · icacls 去掉继承 + 只给 %USERNAME%
  密钥（掩码，只给前 6 位）:
    main          ec7100…（32 位）
    orchestrator  d7bdcc…（32 位）
    supervisor    bd49be…（32 位）
    archivist     34c63a…（32 位）
  ★ 完整值只写在上面的 json 里，页面与报告都不回显完整密钥。
```

`exit = 0`。补充两点：

- `--init` **不写** `archivist_added_at` 字段（那是后来手工加的）⇒ 已按**原字段顺序**把它补回，不丢元数据。
- 补写后又跑了一遍与 `server.mjs` 的 `lockDown()` **同款**的权限收紧：`chmod 600` ✓ · `icacls <file> /inheritance:r`（exit 0）✓ · `icacls <file> /grant:r %USERNAME%:F`（exit 0）✓。

### 2. 怎么让旧的失效

`--init` 是**整份重写**配置文件，不是追加 ⇒ 新文件里只有新生成的四把。已显式核对：

- 新钥匙与旧钥匙**逐一不同**：`differs_from_old = true × 4`
- **旧钥匙在新文件里的残留 = NONE**（逐值比对确认，不是"尽量"）
- 新四把格式校验 `/^[0-9a-f]{32}$/` 全过；`keys` 下**恰好**这 4 个角色，不多不少

⇒ 面板启动时 `byKey` 表只由新文件构建，旧钥匙不在表里 ⇒ 必然 403（见下第 ③ 条实测）。

### 3. 面板怎么重启的（先停、后起、不并存）

**停**（按 `stop.cmd` 的方式）：

```
> taskkill /PID 11348 /F
ERROR: The process "11348" not found.        (exit 128)
```

pid 文件是上次留下的陈旧值，进程实际早已退出。起之前再确认：`18240` 上的监听数 = **0**。

**起**（按 `start.cmd` 的方式）：detached 启动 `node server.mjs`（cwd = `dashboard\`，`stdio: ignore`，`unref()`），12 秒内探到端口就绪。

**结果**：

```

Get-NetTCPConnection → 127.0.0.1 : 18240  OwningProcess = 28912
Get-Process -Id 28912 → node, StartTime = 2026/10/14 20:46:01
```
