## 2. 关键契约

### 2.1 路由

| 路由 | 方法 | 返回 |
|---|---|---|
| `/.dsh-pipeline/panel` | `GET` / `HEAD` | 快照 `{ ok, generated_at, project_root, tasks[], warnings[] }`；其它方法 405；数据源没接线 503 |
| `/.dsh-pipeline/panel?view=archived` | `GET` / `HEAD` | `{ ok, tasks[], warnings[] }`，行里有 `id` / `dir` / `state` / `state_label` / `requirement_snippet` / `archived_at`；只认 `view=archived` 这一个 query |
| `/.dsh-pipeline/panel/action` | `POST` | `{ ok, action, task_id, message? , error?, code? }`；动作请求体上限 8192 字节（超了 413） |

三道闸：**环回**（非环回 403）、**开关门**（关着时 8 个动作一律拒，且不读盘不写盘）、
**跨站闸**（POST 只收 `application/json`，`Sec-Fetch-Site` 只认 `same-origin` / `none`，
`Origin` 必须与 `Host` 同源，`Origin: null` 也拒）。

### 2.2 任务行（键序是契约）

`id, state, state_label, requirement_snippet, updated_at, human_pending, team_board, seats, tier,
pinned, allowed_actions` —— 共 11 个键，顺序固定；`allowed_actions` 永远是最后一个键。
`tier` 只从结构化字段读（`roster.tier` → `task.tier`），认不出就是 `null`，不从需求文本里猜。
`allowed_actions` 只放状态机允许的 `cancel, restore, archive, delete`（pin / 归档行动作不进来）。

### 2.3 8 个写动作

| 动作 | 底层 | 额外闸门 |
|---|---|---|
| `cancel` | `store.transition(event:'cancel', actorRole:'human')` | 开关开 |
| `restore` | `store.transition(event:'unblock', actorRole:'human')` | 开关开 |
| `archive` | `store.purgeTask(mode:'trash', reason:'面板·留档')` | 开关开、仅终态 |
| `delete` | `store.purgeTask(mode:'delete', reason:'面板·删单')` | 开关开、仅终态、`confirm: true` |
| `pin` / `unpin` | `pins.setPinned(…, true/false)` | 开关开、要 `task_id` |
| `unarchive` | `archive.restoreArchived({ dir })` | 开关开、`task_id` 是归档目录名 |
| `delete_archived` | `archive.deleteArchived({ dir, confirm:true })` | 开关开、`confirm: true`、先写墓碑 |

成功文案是固定中文（`已终止：<state>` / `已恢复` / `已留档` / `已删单` / `已置顶` /
`已取消置顶` / `已恢复归档` / `已永久删除`）；失败一律 `ok:false` + 底层拒绝原文，
接线不完整给 `STORE_UNAVAILABLE`，底层抛异常给 `PANEL_ACTION_FAILED`。

### 2.4 落盘位置

| 文件 | 语义 |
|---|---|
| `<项目根>/.pipeline/_panel-pins.json` | 置顶：`{ version: 1, ids: [...] }`，上限 200，原子写，坏文件当空表 |
| `<项目根>/.pipeline/_trash/<任务id>-<时刻>/` | 归档目录（`archive` 的落点）；恢复用 rename 挪回，挡穿越与覆盖 |
| `<项目根>/.pipeline/_purge-log.jsonl` | 永久删除的墓碑账本（`delete` 与 `delete_archived` 共用）；先留痕后动手 |

## 3. 客户端：入口 375 行 + 18 个 chunk

`lib/client.js` 是宿主按 `/plugins/dsh-pipeline/client.js?rev=…` 发布的入口，**375 行**，只做模块注册、
开关、面板 lazy wrapper。面板**第一次被渲染**时才用 `Promise.all` 逐个
`require.async('./client.<name>.js')` 取回 **18 个** chunk（入口 + chunk 共 19 个文件、合计 **4743 行**；
行数只作信号（大小不是死限）），交给 `shell` 按依赖序组装。

- 宿主按 `/plugins/dsh-pipeline/<chunk>?rev=<入口 rev>` 提供同级脚本并 **immutable** 缓存；
- chunk 是**经典脚本**，用 `window.__ModuleLoader__.load({ id, chunk, factory })` 注册，
  必须与入口同目录、彼此**不能**同步 `require` —— 组合只在入口做；
- 协议就是「入口 + 同级文件」，所以**不需要 tsdown、不需要改 `package.json`**。

约束写进了 `plugin/active/CONVENTIONS.md` §4：入口 ≤380 行（当前 375）、chunk 120–350 为宜 / 硬上限
400 只是预警线（大小不是死限）；**新增客户端逻辑一律新开 chunk**，chunk 之间通过 shell 的共享作用域 `S` 或
`create(deps)` 组合。

18 个 chunk（按职责）：`view` 388 / `menu` 335 / `shell` 320 / `actions` 297 / `preview` 296 /
`atoms` 294 / `preview-control` 281 / `portal` 249 / `batch` 240 / `interact` 223 / `batch-bar` 206 /
`preview-bubble` 201 / `seats` 198 / `outside` 196 / `preview-data` 180 / `poll` 168 /
`card-actions` 167 / `controls` 129。

**弹层为什么挂 `document.body`**：宿主会话头部是**窗口拖拽区**，又有自己的层叠顺序与命中区 ——
弹层只要还长在它的 DOM 里，点击就可能被吞掉。所以 ⋯ 菜单与预览浮层用
`ReactDOM.createPortal(children, document.body)` + `position:fixed` 渲染：落点按触发按钮的
`getBoundingClientRect()` 算（右缘对齐 `right = 视口宽 − rect.right`、`top = rect.bottom + 6`、
`min(440, 92vw)` × `min(560, 70vh)`、四周至少留 8px），滚动 / 改尺寸后 100ms 节流重算；点外面用
`target.closest('[data-pipeline-panel]')` 复核，判不出来就不关；取不到 `react-dom` 时回退成原样渲染。

界面行为：任务卡最左 `L0`–`L5` 档位徽标 + 团队人数；悬停 140ms 展开、移开 800ms 收起、点一下钉住；
「⋯」按状态列终止 / 恢复 / 归档 / 删单（删单两击确认）；📌 置顶；头部「批量」→ 圆勾多选 → 底部批量栏
串行执行；头部「归档 N」进归档视图；鼠标停在席位 chip 上在面板左侧弹出约 520×520 的会话预览
（最多 12 行，只显示真实用户 / AI，AI 空正文显示「正在思考…」，点气泡 `openSession` 打开会话）。
面板只保留这些正式行为，没有临时诊断属性或诊断描述器。

## 4. 已验证与未验

**已验证（可复跑）**

- `node tests\run-all.mjs`：4098/4098、126 套（含 `panel-snapshot-check` / `panel-actions-check` /
  `panel-ui-check` / `panel-portal-check` / `client-check`）；每套的原始输出落在
  `tests/<suite>-last-run.txt`。
- 面板契约：键序、摘要 80 码点、待办计数、席位三层、`allowed_actions`、坏 JSON 降级、
  `?view=archived` 路由、`/state` 不回归（74 项）。
- 写动作：8 个动作的参数透传、开关门、`confirm` 严格 `true`、拒绝原文、`_trash` 恢复 / 永久删除、
  墓碑、pins 落盘与上限（99 项）。
- 客户端：入口与 18 个 chunk 一一对应、行数只作信号（大小不是死限）、经典脚本、
  `load({ id, chunk, factory })`、`require.async` 取数、`createPortal` 到 `document.body` 与 fixed
  落点 / 无 `react-dom` 回退；桩 React 下的渲染与点击（`client-check` 30 项、`panel-ui` 14 项、
  `panel-portal` 3 项）。

**未验（真实环境面）**

| 项 | 为什么没验 | 风险 |
|---|---|---|
| 真实浏览器排版 | 本机没有截图能力，只有桩 React | 「长得不好看」大于「不显示」：组件用纯内联样式、不读宿主 CSS 变量 |
| 真机点击链路 | 没在真实 profile 上装并走完「悬停 → 取数 → 点气泡 → 打开会话」 | `sessions.retain` / `uiWorkspace` 的真实形态可能与本机替身不同，失败时是「预览/打开会话不可用」，不影响开关与面板本体 |
| 真实 `_trash` 目录名 | 单测里 `_trash` 是临时造的 | 右锚定剥 `<任务id>-<stamp>` 若遇到不符合 `purge.js` 命名的旧目录，会退回读 `task.json.id` 或目录名 |

排查入口：面板相关拒绝都带中文原因与 `code`；宿主侧只看 `lib/switch-routes.js` 的三条精确匹配，
客户端侧先看浏览器控制台里 `多AI协调团队加载失败：<原因>` 那一行（chunk 取不回来时的降级显示）。
