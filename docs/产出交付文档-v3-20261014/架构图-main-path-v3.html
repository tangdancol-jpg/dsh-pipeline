dsh-pipeline 主路径架构（v3）

三层：DSH 宿主（webServer 路由 / 插件 loader / chunk 服务）→ 插件宿主侧（工具、守门、状态机与面板数据面）→ 浏览器客户端（入口 client.js → require.async → 15 个 chunk → 面板 UI / 预览）。 只画面板这条主路径；守门判定与状态机全部迁移不在此图。

图例

  • 实线箭头：调用 / 请求 / 注册（谁主动找谁）
  • 虚线箭头：只读取会话事件（不写任何东西）
  • 圆角框：一个可独立说明的部件（文件名 = 落点）
  • 色带：一层（① 宿主 / ② 插件宿主侧 / ③ 浏览器）

主路径怎么走

  1. 装载与注册：DSH 的插件 loader 调 apply(ctx) 装载插件； 插件把 /.dsh-pipeline/panel、?view=archived 与 /panel/action 三条精确匹配路由注册进宿主的 webServer（同一个 /.dsh-pipeline 前缀），把 pipeline_* 工具与单调守卫注册进工具层。 路由处理器拿到的三个数据源（快照 / 归档 / 动作执行器）由 index.js 注入 —— 路由层不猜目录、不判动作白名单。
  2. 读路径：面板每 5 秒 GET /.dsh-pipeline/panel（页面隐藏时跳过）， 路由把请求原样递给 lib/panel/snapshot.js。快照只扫 <项目根>/.pipeline/T-*/task.json 的**结构化字段**：状态、需求摘要（80 码点）、 席位、待办计数、任务板编号、档位、置顶、allowed_actions。坏 JSON 只进 warnings[]，绝不把面板打成 500；归档视图走 ?view=archived，读 _trash/。
  3. 写路径：POST /.dsh-pipeline/panel/action 先过三道闸：环回、 开关开、同源 JSON（Origin 与 Host 同源、请求体 ≤ 8 KB）。动作白名单、 二次确认与执行都在 lib/panel/actions.js：cancel / restore 走 store.transition，archive / delete 走 store.purgeTask，pin / unpin 写 _panel-pins.json，归档两件走 _trash 与 _purge-log.jsonl 墓碑。
  4. 客户端加载：入口 client.js 由宿主按 /plugins/dsh-pipeline/client.js?rev=… 当经典脚本发布，注册后由面板的 lazy wrapper 在**首次渲染**时 require.async 取 14 个同级 chunk（宿主按 rev 缓存，immutable）； chunk 之间不能同步 require，所以组合只在入口做 —— 交给 shell 的共享作用域与 create(deps)。
  5. 预览：悬停席位 chip 时，预览 chunk 用 sessions.retain 拿会话引用、读事件窗口、**读完立刻释放**（最多同时留 3 个）， 只渲染真实用户 / AI 文本；AI 还没吐正文显示「正在思考…」；点任意气泡走 openSession 打开该会话。
自包含单文件：内联 SVG + 内联样式，无外链、无脚本依赖，可离线打开；深色 / 浅色都按 prefers-color-scheme 自动适配（右上角按钮可手动切换）。 契约细节见 2026-10-18-面板与客户端分块.md， 设计取舍见 design/panel/01-面板设计.md。 上一版 架构图-main-path-v2.html 保留作历史。
