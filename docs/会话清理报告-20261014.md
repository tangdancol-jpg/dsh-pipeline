### 2. 「归档」这个动作到底做了什么 ★

DSH 自带**只有归档，没有删除**。asar 里 `WorkspaceRegistry.archiveSession` 的实现是：

```js
await this.setState({ ...state,
  archivedSessionIds: [...state.archivedSessionIds, sessionId],
  pinnedSessionIds: state.pinnedSessionIds.filter(id => id !== sessionId) })
```

⇒ **归档 = 往 `workspace.json` 的 `global.archivedSessionIds` 加一个 id 字符串**。
**它一个文件都不移动**，工件、工程记录、投影缓存全部原地不动。源码注释原文：
> *Archiving never touches workspace accounting — an archived session keeps its `sessionIds` slot so unarchiving restores its position.*

持久化层 `dsh-session-persistence-jsonl` 自己的文档也写着：
> **Nothing deletes session files** — logs accumulate under `root` until removed externally; **the seam has no deletion API**.

侧边栏可见性由 `sessionVisible()` 决定：`origin === "subagent"` 的一律不显示；`blank` 且非当前会话的不显示；`archivedFilter` 默认隐藏已归档的。

### 3. 索引会不会不同步 ★

**会，而且是双向的：**
- 只删磁盘文件、不改索引 ⇒ `workspace.json` 里留下幽灵 id（`sessionIds` 仍指向不存在的会话）；
- 只改索引、不通知宿主 ⇒ **不生效**。宿主把 `workspace.json` 的状态缓存在内存里（`requireState()`），`baseline()` 返回的是**内存值**，不是重新读盘。所以手改 `workspace.json` 在 DSH 运行期间不会反映到侧边栏，并会在宿主下一次 `setState` 时被覆盖。

⇒ 结论：**必须走宿主进程内的入口**（插件路由 / GUI），手工改盘不可靠。

## 六、风险与未做

1. **8 条宿主内存残留行**。`<session-id> / <session-id> / <session-id> / <session-id> / <session-id> / <session-id> / <session-id> / <session-id>` 在删除时是 `open=true, agent=true`（宿主仍持有活 Agent）。它们的**工件已删、`workspace.json` 记账已摘、projcache 已清**，但插件的 `catalog` 仍从宿主内存列出它们。插件已按设计 emit `api-session/removed`，**侧边栏的行会立即消失**；宿主内存那一份会随 Agent 释放或 DSH 下次启动自然清掉。**这不是索引不同步，是宿主内存的生命周期问题**，无需处理（也不许重启 DSH）。
2. **未按原计划单独执行「归档」这一步**。DSH 的归档只写 `global.archivedSessionIds`，且宿主把该状态缓存在内存里，手改 `workspace.json` 在运行期不生效、还会被宿主覆写；而插件的删除本身就会清掉归档/置顶集合并让行立刻消失。故「先归档」在最终状态上被删除动作完整覆盖。**归档集与置顶集清理后均为 0，与原始值一致。**
3. **`sessions\` 下 74 个空的 `<cwd编码>` 分组目录未动**。它们是 DSH 按 cwd 建的分组壳，删掉会话后自然变空；不属于本次授权范围，且删空目录对侧边栏无影响，故**一律保留**。
4. **附件 blob 未删**（`~/.dsh/attachments/v1/objects/<hash>`）。它是内容寻址去重仓库、多会话共享、服务无引用计数 —— 插件自己的「已知边界」也明确不删。本次未碰。
5. **未安装、未重启 DSH、未修改任何插件**。全程只调用插件既有 HTTP 路由；`better-dsh-session-deletetool` 的四个文件字节未改。
6. **未做的事**：没有动 `<session-id>`（拿不准）；没有动 4 个未点名的真实会话与 2 个空会话；没有删 `sessions-archive` 之外的任何目录树；没有使用通配符删除。
