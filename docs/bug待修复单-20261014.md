### P0-3 未消费升级链在【终态单】上无限套娃（活锁）
**状态**：【已修（待活体验收）】
**一句证据**：A/B 探针（隔离两棵树、5 轮生产形状巡检回放）—— **改前每轮继续加深，改后第 2 轮起恒为 0**。

**现象**：机制对「一条投递已送达但没人接管」这件事，会生成一条新的投递去提醒；而那条新投递**同样没人接管**，于是又生成一条升级……**层层套娃、只增不减**。

**实测证据（交付键本身即证据）** —— 同一张单 `T-20261014-hello01`（状态：已取消），连续收到：
```
hello01|unresolved-wake|…|human|no-stable-identity
  → hello01|unconsumed-delivery|…|…|unresolved-wake|…
  → hello01|unconsumed-delivery|…|unconsumed-delivery|…|unresolved-wake|…
  → hello01|escalation|…|unconsumed-delivery|…|unresolved-wake|…#escalated
  → …（继续加深）
```
每一层都是**新键**（`requestId` 幂等只保证同一键不重复，挡不住"每层一个新键"）。

**为什么无法自愈（要害）**：目标单已是**终态**（已取消）⇒ 状态机明示「**无合法事件**」⇒ **主对话没有任何动作能"消费"它**。
**已做的止血**：关闭总开关（`pipeline_switch { on: false }`，修订号 21，2026-10-14T10:52:07Z）。
**根治（三条修法，A 路全做）**：① 终态单不进巡逻与升级链 ② 升级链加深度上限 ③ 升级键收敛到根事件。
**报告**：`A路-终态过滤包-实现报告.md`（39,132 B）§二·§三·§六.2
**★ 验收方法学（A 路留下的一条经验）**：存量账本上两道闸**一条都挡不下**（那 26 条机制通知大多已被 `consumed`/`escalated` 吃掉）
⇒ **光看存量快照看不出修了什么**；这类"链式放大"的验收**必须跑增量动力学**，不能只看快照。
**★ 已知边界**：终态单仍可能收到**至多 1 条** `escalation`（实测 `cancelled` 单 5 轮里 1 条、之后恒 0），
因为升级入口 `index.js:701` **不看任务状态**；本包保证的是"**到此为止、不加深**"，不是"0 条"。收口给出一行补丁（A路 §六.2）。
