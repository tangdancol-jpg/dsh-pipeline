# dsh-pipeline — исходный код плагина, документация по поставке и панель управления
[中文](README.md) | [English (US)](README.en-US.md) | [日本語](README.ja.md) | **Русский**

`dsh-pipeline` — плагин конвейера многоагентного взаимодействия для DSH: основная беседа только распределяет задачи и сама работу не выполняет, а роли написания / тестирования / проверки строго разделены;
выход за рамки полномочий, пропуск шагов и закрытие задачи без OK блокируются кодом до выполнения инструмента. Репозиторий содержит исходный код плагина, отчёты о реализации по каждому раунду и документацию по поставке, а также локальную панель управления только для чтения.

## 1. Исходный код плагина: `plugin/active/`

`plugin/active/` — единственная копия; она соответствует файлам, которые после установки находятся в `profiles/desktop/node_modules/dsh-pipeline/`.
(Ранее рядом существовала старая монолитная версия до рефакторинга — `plugin/src/`; она устарела и нигде не использовалась, поэтому была удалена; в истории она сохраняется.)

### Структура модулей

Точка входа — `index.js`, реализация находится в `lib/`. Пять исходных файлов размером более тысячи строк каждый разделены по темам на подкаталоги,
а исходные файлы сохранены как фасады (имена экспорта не изменились, поэтому вызывающему коду не нужно менять импорты):

| Фасад | Подкаталог | Содержимое |
|---|---|---|
| `lib/store.js` | `lib/store/` | Хранение задач: чтение и запись на диск, критерии хаба супервизора, предусловия переходов состояний, отправка передач, вмешательство человека… |
| `lib/tools.js` | `lib/tools/` | Определения инструментов `pipeline_*`, сгруппированные по инструментам |
| `lib/guard.js` | `lib/guard/` | Защита (guard): классификация прав чтения и записи ролей, места (seats) и область полномочий, критерии для shell, раскрытие скриптов, основное решение |
| `lib/handoff.js` | `lib/handoff/` | Передачи (handoff): таблица полей, проверка, сканирование содержимого, запись |
| `lib/wakeup.js` | `lib/wakeup/` | Пробуждение (wakeup): ключи пробуждения, идентичность журнала, доставка, механизм пробуждения |

Номера строк вида `lib/store.js:2471` в отчётах в `docs/` относятся к единому файлу до разделения.
Текущее расположение следует искать в соответствующем коде в `lib/` текущего дерева исходников.

Две более новые подсистемы также разделены по функциям (а не одним большим файлом):

| Каталог | Содержимое |
|---|---|
| `lib/transport/` | Интерфейс каналов и реализации: `session` (полноценная сессия) / `team` (официальные Agent Teams) / `subagent` / `manual` / `simulated`; `createTransport()` — единственная точка выбора |
| `lib/team/` | Адаптер официальных Agent Teams: именование, проверка канала, внедрение персоны роли, закрепление четырёх слотов, доставка, зеркалирование доски задач |

### Тесты

```bash
cd plugin/active
node tests/run-all.mjs            # 全套；结果写到 tests/last-run.txt
node tests/<套件>.mjs             # 单跑一套
```

- Полный набор сейчас проходит **3528/3528** (108 наборов).
- Часть наборов требует **хостовой установки** (`DSH_APP_ASAR=<установка DSH>/resources/app.asar`) или хостовых пакетов (`@deepseek-ai/dsh-tools`, `@deepseek-ai/cordis`); если их нет, это явно отмечается, и они не включаются в процент прохождения. На этой машине: с `DSH_APP_ASAR` — 3528/3528; без него 3 проверки пресетов красные (это особенность окружения, а не дефект кода).
- `tests/seat-liveness-wake-check.mjs` не зарегистрирован в полном наборе, а его содержимое устарело относительно нынешних критериев потери связи, поэтому при отдельном запуске он падает.

### Установка

`plugin/active/install.ps1` копирует рабочие файлы в профиль DSH и регистрирует плагин; `rollback.ps1` выполняет откат.
После изменения кода нужно перезапустить DSH (или перезагрузить плагин), чтобы изменения вступили в силу в работающем процессе.

## 2. Панель управления: `dashboard/`

Локальная одностраничная панель только для чтения для управляющих ролей (основная беседа / анализ требований / супервизор / архив); при каждом запросе она читает
заявки на требования, заявки об ошибках и журналы изменений в `docs/`. Она слушает только `127.0.0.1`, и для просмотра нужен ключ.
Запуск и остановка: `dashboard\start.cmd` / `dashboard\stop.cmd`; подробности см. в [`dashboard/README.md`](dashboard/README.md).

## 3. Документация: `docs/`

Документация для разработчиков, по одному вопросу на файл, находится в [`docs/`](docs/README.md):

- [`docs/install.md`](docs/install.md) — установка, параметры, что изменяют скрипты, откат
- [`docs/directory-settings.md`](docs/directory-settings.md) — откуда берутся каталог установки / рабочий каталог и как их переопределить
- [`docs/encoding-conventions.md`](docs/encoding-conventions.md) — для `.ps1` нужен UTF-8 BOM, для остальных — нет; окончания строк LF
- [`docs/sandbox-temp-root.md`](docs/sandbox-temp-root.md) — если `%TEMP%` оказывается внутри workspace, все ограниченные оболочки перестают работать
- [`docs/manifest.md`](docs/manifest.md) — правила проверки и генерации `MANIFEST.sha256`
- [`docs/agent-teams.md`](docs/agent-teams.md) — интеграция официальных Agent Teams (`transport: 'team'`): границы возможностей, конфигурация, новые списки guard, зеркалирование доски задач, диагностика

Кроме того, остались артефакты периода поставки: `产出交付文档-v3-20261014/` (включая схему архитектуры `架构图-main-path-v2.html`).

**В документации никогда не указываются локальные пути машины**: используются `%USERPROFILE%\.dsh\…`, `$HOME`, `<path\to\thing>` или относительные пути;
адрес панели записывается как `127.0.0.1:18240`; исходные значения, такие как идентификаторы сессий, не сохраняются и записываются как `session-…`.

## 4. Проверка

`MANIFEST.sha256` — это sha256 каждого файла, кроме самого себя. Выполните в корне репозитория:

```bash
sha256sum -c MANIFEST.sha256
```

После изменения файлов его нужно перегенерировать (точные правила и альтернативная команда для Windows — в [`docs/manifest.md`](docs/manifest.md)).
